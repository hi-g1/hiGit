# 로드맵

짧은 반복으로 진행한다. 반복마다 "동작하는 앱"이 남아야 한다. 범위는 반복을 마칠 때마다 다시 정한다. 각 반복의 상세 계획은 `planner`가 `docs/plans/`에 쓴다.

## 반복 0: 뼈대
- Tauri 2 + React + TS 프로젝트, Rust 워크스페이스(app, core, git, hosting, platform, watcher).
- `GitBackend` 트레이트와 `CliBackend`의 status, log만.
- `Action` 레지스트리, 실행기, 조회용 Query, `Term` 부품과 glossary(ko, en), 디자인 토큰.
- 버전 기록은 단순 목록(노선도는 아래 "노선도 보기").
- 첫 실제 Action: 버전 관리 시작(init). 저장소가 아닌 폴더를 열면 안내 문구 옆에 그 버튼.
- Windows·Ubuntu CI(빌드 + 테스트).
- 완료 기준: 폴더를 열면 바뀐 파일 목록과 버전 기록이 보이고, 용어에 호버하면 원래 이름이 뜬다.

## 반복 1a: 기반과 내 컴퓨터 안의 작업 (2026-10-15 완료. CI 초록 9f4ef1e, 두 OS 수동 확인은 사용자가 따로)
- 기반: 타입 있는 액션 입력(D-020), 저장소 git hook(D-022), CI Windows artifact(crt-static).
- 용어·디자인 개편: 이미 아는 말(D-024), 상단 바 + 2단(D-025), 먹색 모노(D-026), 문구 규칙(D-027). 계획 002.
- 이번 버전에 넣기·빼기, 버전 저장, 비교 보기.
- 파일 변경 감시(.gitignore 대상 제외, 실패 시 창 포커스 새로 고침), 상단 상태 표시.

## 반복 1b: 브랜치와 원격 (2026-10-16 완료. 두 OS 수동 확인은 docs/progress.md "사람이 할 일")

- 브랜치 목록에서 바로 갈아타기·찾기 칸에서 새 브랜치, 고친 파일 맡겨 두기(D-047).
- 동기화 버튼 하나와 저절로 하는 원격 확인(D-045). 계획 001 20단계의 새로 고침·가져오기·올리기 세 버튼을 대체하고 새로 고침 버튼은 없앤다. SSH 질문 끄기(D-023).

- 보안 1b 단계(D-034~D-041, 계획 004).
- 시작 화면: 앱을 켜면 마지막 프로젝트 바로 열기, 최근 프로젝트, 상태 문장, 프로젝트 메뉴, Ctrl+O(D-031~D-033, 계획 003). 완료.
- 큰 새 파일 비교 상한(계획 001 10b).

## 반복 3: 기록 다루기 (계획 008, 결정 D-097~D-108)
- 마지막 버전 고치기, 되돌리기, 이 버전으로 돌아가기, 기록 정리, 이 버전만 복사하기, 태그.
- 역 메뉴의 기능은 반복 2b의 노선도 위에서 동작한다: `features/history/menu/items.ts` 표에 항목을 더하고 `run`에서 core 액션을 부른다(역 해시는 core가 다시 확인). 기록 정리는 카드 지도(D-017), 여러 역 선택도 이때.
- 반복 2b에서 넘긴 것: "이때 파일 보기"(D-105로 넣음).
- 브랜치 지우기·이름 바꾸기(D-084, D-103). 앱이 시작한 복사·되돌리기·기록 정리의 충돌은 충돌 화면에서(D-101).
- 올린 기록은 바꾸지 않는다(D-097). 반복 4 이후로 넘김: 설정 화면 + 덮어쓰며 올리기 + 올린 기록 바꾸기, 원격 브랜치 지우기·이름 바꾸기, 태그 올리기.
