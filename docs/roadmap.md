# 로드맵

짧은 반복으로 진행한다. 반복마다 "동작하는 앱"이 남아야 한다. 범위는 반복을 마칠 때마다 다시 정한다. 각 반복의 상세 계획은 `planner`가 `docs/plans/`에 쓴다.

## 반복 0: 뼈대
- Tauri 2 + React + TS 프로젝트, Rust 워크스페이스(app, core, git, hosting, platform, watcher).
- `GitBackend` 트레이트와 `CliBackend`의 status, log만.
- `Action` 레지스트리, 실행기, 조회용 Query, `Term` 부품과 glossary(ko, en), 디자인 토큰.
- 버전 기록은 단순 목록(노선도는 아래 "노선도 보기").
- 첫 실제 Action: 버전 관리 시작(init). 저장소가 아닌 폴더를 열면 안내 문구 옆에 그 버튼.
- Windows·Ubuntu CI(빌드 + 테스트).
- 완료 기준: 폴더를 열면 바뀐 파일 목록과 버전 기록이 보이고, 용어에 호버하면 원래 이름이 뜬다.

## 반복 1a: 기반과 내 컴퓨터 안의 작업 (2026-10-15 구현 완료, 두 OS 수동 확인 남음)
- 기반: 타입 있는 액션 입력(D-020), 저장소 git hook(D-022), CI Windows artifact(crt-static).
- 용어·디자인 개편: 이미 아는 말(D-024), 상단 바 + 2단(D-025), 먹색 모노(D-026), 문구 규칙(D-027). 계획 002.
- 이번 버전에 넣기·빼기, 버전 저장, 비교 보기.
- 파일 변경 감시(.gitignore 대상 제외, 실패 시 창 포커스 새로 고침), 상단 상태 표시.

## 반복 1b: 브랜치와 원격
- 브랜치 만들기·바꾸기, 새로 고침·가져오기·올리기(SSH 질문 끄기, D-023).
- 시작 화면: 앱을 켜면 마지막 프로젝트 바로 열기, 최근 프로젝트, 상태 문장, 프로젝트 메뉴, Ctrl+O(D-031~D-033, 계획 003).
- 큰 새 파일 비교 상한(계획 001 10b).

## 반복 2: 합치기와 복구
- 합치기(미리보기, 끌어놓기), 충돌 해결 화면(D-028 1안), 임시 보관, 변경 취소.
- 백업 참조, UndoJournal, "방금 작업 취소", 복구 화면.

## 반복 3: 기록 다루기
- 마지막 버전 고치기, 되돌리기, 이 버전으로 돌아가기, 기록 정리, 이 버전만 복사하기, 태그.

## 반복 4: GitHub
- 로그인(device flow), 검토 요청 목록·만들기, 복제(시작 화면 "복제" 글자와 Ctrl+Shift+O 포함).

## 반복 5: OS 통합과 배포
- 폴더 우클릭 메뉴(Windows, Nautilus), 단일 인스턴스, 설치 파일(.msi, .deb, AppImage).

## 따로 둔 항목: 버전 기록 노선도 보기
- 시기 미정. D-017(제안)이 확정되면 반복 사이에 배치한다. 반복 1 이후 아무 때나 넣을 수 있다.
- 노선도 + 확대·축소 + 선 굵기로 버전 기록 그리기(`docs/research/git-visualization.md` "추천 조합").
- `docs/architecture.md` "버전 기록 그리기 계층"대로 배치 계산과 그리기를 나누고 SVG로 시작한다.
- 시작 화면의 큰·작은 노선도도 같은 코드로 그린다(계획 003 N1~N3).
- 세이브 카드(복구)는 반복 2, 카드 지도(기록 정리)는 반복 3의 해당 화면에서 같은 결정을 따른다.
