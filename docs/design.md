# 디자인 규칙 (Design)

방향: **담백하고 깔끔하게.** 틀은 무채색이고 주 버튼은 흑연색 채움이다. 파랑은 선택·포커스·링크에만 쓰고, 그 밖의 색은 브랜치 선·파일 상태·위험 작업처럼 뜻이 있을 때만 쓴다(D-026). 그림자·그라데이션·이모지·과한 둥근 모서리를 쓰지 않는다. "AI가 만든 템플릿" 느낌의 원인(보라-파랑 그라데이션, 큰 카드 그림자, 의미 없는 아이콘 남발, 모든 곳에 둥근 배지, 괄호로 덧붙인 설명)을 피한다.

## 색 토큰
`src/styles/tokens.css`에 CSS 변수로 둔다. 화면 코드에 색 값을 직접 쓰지 않는다. 대비는 `src/styles/contrast.test.ts`가 라이트·다크 모두 확인한다(글자 4.5:1, 테두리·포커스·주 버튼 경계 3:1 이상).

## 글꼴
- 본문: **Pretendard** (한글·영문 균형, OFL 라이선스, npm 패키지로 앱에 포함, D-014). 대체: `system-ui`.
- 코드·해시·파일 경로: **JetBrains Mono** (OFL, latin 부분만 포함, D-014). 한글은 Pretendard로 이어 받고, 그다음 대체는 `ui-monospace`.
- 크기: 13px(기본), 12px(보조), 15px(화면 제목, 시작 화면 상태 문장), 20px(시작 화면 처음 실행 제목, 홈의 버전 이름 칸 `--font-size-name`), 26px(시작 화면 프로젝트 이름, `--font-size-display`). 줄 간격 1.5.
- 굵기는 400과 600 두 가지만. JetBrains Mono는 400만 포함한다(D-014).

## 배치
- 작업 공간은 상단 바 + 2단이다(D-025).
- 상단 바 왼쪽은 프로젝트 메뉴와 브랜치 단추, 오른쪽은 동기화와 버전 기록(D-045, D-058). 컨트롤은 5개 이하. 아이콘만 있는 버튼에는 툴팁.
- 왼쪽 칸은 320px(최소 280px)로 "변경 사항 · 버전 기록" 탭과 버전 저장 상자. 오른쪽 칸은 나머지 폭으로 비교 보기.
- 칸 사이는 간격 없이 `--border` 1px 선으로 나눈다. 작업 공간의 칸에는 둥근 모서리와 그림자를 쓰지 않는다.

## 간격과 모양
- 간격 단위 4px: 4, 8, 12, 16, 24, 32.
- 모서리: 버튼·입력 6px, 떠 있는 패널 8px. 원형은 아바타만.
- 그림자: 떠 있는 것(메뉴, 대화상자, 툴팁)에만 `0 4px 16px rgba(0,0,0,.08)`.
- 아이콘: Lucide, 16px, 선 굵기 1.5. 글자 없이 아이콘만 있는 버튼에는 반드시 툴팁.

## 부품 규칙
- **버튼**: 화면마다 주 버튼은 하나(`--primary` 채움, 글자 `--primary-text`). 나머지는 테두리 버튼 또는 글자 버튼. 글자 버튼은 본문색(`--text`)이고 파랑이 아니다.
- **위험 버튼**: `danger` 액션은 글자색 `--deleted` 테두리 버튼, 확인 대화상자에서만 채움.
- **체크 상자·입력칸**: 테두리 `--border-strong`. 체크 상자 켜짐은 `--primary` 채움.
- **Term 툴팁**: 지연 400ms, 위쪽 우선. 내용 세 줄: 원래 이름(600) · 명령(모노) · 설명(muted).
- **목록 행**: 높이 32px, 호버 시 `--surface-hover`, 선택 시 왼쪽 2px `--accent` 막대.
- **상태 표시**: 색만으로 알리지 않고 글자나 기호를 함께 쓴다(추가 `+`, 삭제 `−`, 파일 상태 이름).
- **빈 상태**: 그림 대신 한 줄 설명과 버튼 하나, 왼쪽 정렬.
- **굵은 글자 버튼**: 테두리 없이 600 굵기. 옆에 단축키를 `--text-muted` 12px 코드 글꼴로(시작 화면 상단 바의 "폴더 열기 Ctrl+O", D-033).
- **버전 이름 칸**: 파일 목록 위에 테두리 없는 큰 글자(600)로 이름, 바로 아래 설명(D-044). placeholder는 제안 이름과 "설명 추가"(`--text-muted`). 포커스는 `--accent` 밑줄 2px. 오른쪽 아래에 옅은 `Ctrl+Enter`와 주 버튼.
- **토스트**: 바로 한 일의 결과를 화면 아래 가운데에 8초 띄운다(D-042). `--surface` 바탕, `--border` 테두리, 떠 있는 그림자. 결과 문구 + 굵은 글자 버튼("되돌리기") + 옅은 단축키. 마우스를 올리면 멈춘다. 한 번에 하나.
- **흐린 줄**: 투명도를 쓰지 않고 글자를 `--text-muted`로 바꾼다(대비 테스트가 투명도를 계산하지 못한다).
- **움직임**: 150ms ease-out, 페이드와 4px 이동만. `prefers-reduced-motion`이면 끈다.

## 문구 (D-027, D-024)
- 괄호로 덧붙이는 설명을 쓰지 않는다. 예: "합치기 그만두기 (원래대로)" → "합치기 그만두기".
- 버튼은 한 가지 동작을 동사로 끝나는 짧은 말로 쓴다. 목적어는 붙여도 된다(예: "폴더 열기").
- 보충 설명은 `<Term>` 툴팁, 일반 툴팁, 또는 둘째 줄로 보여준다.
- 존댓말 해요체로 통일한다. 합쇼체("~합니다")를 섞지 않는다.
- 한 낱말은 한 기능에만 쓴다. 예: "가져오기"는 pull에만, "원격 확인"은 fetch에만(D-059).
- 용어 호버 설명은 동작이면 "~하기", 대상이면 명사로 끝낸다. "~않음·~함·~사라짐" 같은 메모체를 쓰지 않는다. 주의할 내용은 둘째 문장에 "~요"로 쓴다.
- `src/messages/copy-rules.test.ts`가 괄호, 옛 용어, 합쇼체를 확인한다.

## 시작 화면 색 (D-031)
- 큰 노선도("마지막으로 하던 곳")의 선과 점만 브랜치 색(`--graph-*`). 노선도 옆 글자("지금 여기", 브랜치 이름, 버전 이름)는 `--text`·`--text-muted`로 쓴다(다크에서 그래프 색은 글자 대비에 못 미친다).
- 작은 노선도(목록 줄)는 `--border-strong`, 갈라진 브랜치만 `--text-muted`.
- 상태 글자는 `--text`이고 충돌만 `--deleted`.

## 다크 모드
시스템 설정을 따르고 설정에서 라이트/다크/시스템 선택. 토큰만 바꾸고 부품 코드는 같다.

## 확인 사항
- Windows(WebView2)와 Ubuntu(WebKitGTK)에서 글꼴 렌더링과 스크롤바 모양을 매번 비교한다. 스크롤바는 CSS로 얇게 통일.
- 한글 입력: 버전 저장 메시지 입력창에서 조합 중 Enter가 저장을 실행하지 않게 `isComposing`을 확인한다.
- Windows 고대비(WebView2의 `forced-colors: active`)에서 주 버튼·체크 상자가 보이는지 확인한다. WebKitGTK는 GTK 고대비 테마를 웹 내용에 적용하지 않는다.
