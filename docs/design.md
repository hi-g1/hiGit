# 디자인 규칙 (Design)

방향: **담백하고 깔끔하게.** 틀은 무채색이고 주 버튼은 흑연색 채움이다. 파랑은 선택·포커스·링크에만 쓰고, 그 밖의 색은 브랜치 선·파일 상태·위험 작업처럼 뜻이 있을 때만 쓴다(D-026). 그림자·그라데이션·이모지·과한 둥근 모서리를 쓰지 않는다. "AI가 만든 템플릿" 느낌의 원인(보라-파랑 그라데이션, 큰 카드 그림자, 의미 없는 아이콘 남발, 모든 곳에 둥근 배지, 괄호로 덧붙인 설명)을 피한다.

- 라이트 `--border-strong`은 `--surface-sunken` 위에서 대비가 3:1에 못 미친다. sunken 바탕 위의 입력칸 테두리로 쓰지 않는다.
- 대비 테스트는 `--on-deleted`/`--deleted`, `--text`·`--text-muted`/`--conflict-ours-bg`·`--conflict-theirs-bg`도 4.5:1로 확인한다.
- 대비 계산값은 `docs/plans/002-terms-and-design-refresh.md` "색 토큰" 표에 있다.

브랜치 그래프 선 색은 채도를 낮춘 6색을 순서대로 쓴다(`--graph-1`~`--graph-6`): 라이트 `#3A6EA5`, `#2F7D4F`, `#9A6110`, `#7A5BA6`, `#2E7F86`, `#8A5A44`, 다크 `#7FA7D6`, `#6BBF8A`, `#D9A54A`, `#B59AE0`, `#5FBCC4`, `#C9967A`(D-094). 두 모드 모두 `--bg`·`--surface`에서 3:1 이상(그래픽 기준)이고 글자에는 쓰지 않는다. 현재 브랜치는 색이 아니라 "지금 여기" 표시와 굵기로 구분한다.

브랜치마다 색은 `src/features/branches/color.ts`의 `branchColor(이름, 기본 브랜치)` 하나로 정한다. 기본 브랜치는 `--graph-1`, 나머지는 이름 해시로 `--graph-2`~`--graph-6`이라 같은 브랜치는 어느 화면에서나 같은 색이다. 상단 바 브랜치 단추의 점, 브랜치 목록의 점, 홈 노선도의 선과 역이 이 함수를 쓴다. 글자에는 쓰지 않는다(D-031).

## 글꼴
- 본문: **Pretendard** (한글·영문 균형, OFL 라이선스, npm 패키지로 앱에 포함, D-014). 대체: `system-ui`.
- 코드·해시·파일 경로: **JetBrains Mono** (OFL, latin 부분만 포함, D-014). 한글은 Pretendard로 이어 받고, 그다음 대체는 `ui-monospace`.
- 크기(D-138, D-146): 14px(본문 `--font-size-md`, 코드 `--font-size-code`), 13px(보조 `--font-size-sm`), 17px(화면 제목·시작 화면 상태 문장 `--font-size-title`), 22px(시작 화면 처음 실행 제목, 홈의 버전 이름 칸 `--font-size-name`), 28px(시작 화면 프로젝트 이름 `--font-size-display`). 12px보다 작은 글자는 없다. 줄 간격 1.5.
- 단위: 크기 토큰은 모두 rem이고 이 문서의 px 숫자는 화면 배율 1일 때의 디자인 값이다. 루트 글자 크기 = 16px × 배율이고 배율은 OS 기본 본문(Windows 14, Ubuntu 15)과 OS 글자 배율, 설정 "글자 크기"(작게·보통·크게·아주 크게, Ctrl+=·Ctrl+−·Ctrl+0)로 정한다. 선·테두리·그림자는 px 그대로.
- 굵기는 400과 600 두 가지만. JetBrains Mono는 400만 포함한다(D-014).

## 배치
- 작업 공간은 상단 바 + 2단이다(D-025).
- 상단 바 왼쪽은 프로젝트 메뉴와 브랜치 단추, 오른쪽은 동기화·버전 기록·작업 내역(D-045, D-058, D-085). 버전 기록과 작업 내역은 `--text-muted` 글자 버튼이고 켜져 있으면 굵게. 컨트롤은 5개 이하. 아이콘만 있는 버튼에는 툴팁. 합치는 중에는 브랜치 단추 대신 이름 글자만 두고 오른쪽 컨트롤을 숨긴다.
- 상단 바는 폭이 모자라면(800px·"아주 크게") 오른쪽 컨트롤 묶음이 통째로 아랫줄로 내려간다. 가로 스크롤은 생기지 않는다.
- 상단 바 바로 아래에 알림 줄이 쌓인다(아래 "알림 줄").
- 왼쪽 칸은 280~340px(큰 배율에서도 창 폭의 45%까지)로 버전 이름 칸과 고친 파일 목록. 오른쪽 칸은 나머지 폭으로 비교 보기와 맨 아래 줄(아래 "비교 칸 아래 줄").
- 칸 사이는 간격 없이 `--border` 1px 선으로 나눈다. 작업 공간의 칸에는 둥근 모서리와 그림자를 쓰지 않는다.
- **칸 나눔선**(D-164): 왼쪽 칸 오른쪽 1px 선을 끌어 폭을 바꾼다(잡는 영역은 양쪽 4px, 호버하면 좌우 화살표 커서와 `--border-strong`). 15rem~칸들 폭의 50%, 더블클릭은 기본 폭, Tab으로 닿으면 ←·→로 1rem씩. 홈·충돌 화면 파일 목록·"이때 파일 보기" 목록이 같은 부품을 쓰고 폭은 화면마다 앱 데이터에 rem으로 저장한다.

## 간격과 모양
- 간격 단위 4px: 4, 8, 12, 16, 24, 32(rem 토큰 `--space-1`~`--space-8`).
- 모서리: 버튼·입력 6px, 떠 있는 패널 8px. 원형은 아바타만.
- 그림자: 떠 있는 것(메뉴, 대화상자, 툴팁)에만 `0 4px 16px rgba(0,0,0,.08)`.
- 아이콘: Lucide, 16px, 선 굵기 1.5. 글자 없이 아이콘만 있는 버튼에는 반드시 툴팁.

## 부품 규칙
- **버튼**: 화면마다 주 버튼은 하나(`--primary` 채움, 글자 `--primary-text`). 나머지는 테두리 버튼 또는 글자 버튼. 글자 버튼은 본문색(`--text`)이고 파랑이 아니다.
- **위험 버튼**: `Button`의 `danger` 변형은 `--deleted` 채움에 글자 `--on-deleted`(600)이고, 되돌릴 수 없는 일의 확인 대화상자에서만 쓴다(고친 것 버리기, 멈춘 작업 정리, 강제로 멈추기). 대화상자를 여는 단추는 테두리 버튼이나 옅은 글자이고 위험 색을 채우지 않는다(고친 것 버리기만 호버 때 글자가 `--deleted`).
- **확인 대화상자**: 떠 있는 판(`--surface`, `--radius-panel`, `--shadow-float`, 뒤는 `--overlay`), 폭 440px까지. 제목 15px(600)에 무엇을 하는지 짧은 문장, 그 아래 대상 파일 이름을 코드 글꼴 12px `--text-muted`로. 오른쪽 아래에 위험 버튼과 주 버튼 "닫기"(주 버튼은 안전한 쪽, TrustDialog 방식).
- **체크 상자·입력칸**: 테두리 `--border-strong`. 체크 상자 켜짐은 `--primary` 채움.
- **Term 툴팁**(D-140, D-154): 글자에 밑줄·점선·`help` 커서 없이 툴팁만. 지연 600ms(다른 툴팁은 400ms), 위쪽 우선. 내용 세 줄: 원래 이름(600) · 명령(모노) · 설명(muted). English에서 화면 이름과 원래 이름이 같으면 이름 줄을 뺀다. 설정 "용어 설명 보기"를 끄면 툴팁도 포커스도 없다.
- **밑줄과 글자 버튼**(D-140): 버튼·상단 바 글자에는 밑줄을 쓰지 않는다. 글자 버튼은 호버하면 `--surface-hover` 바탕(토스트 단추는 `--primary-hover`). 밑줄은 문장 속 링크 모양(`linkStyle`)에서 호버할 때만.
- **포커스 테두리**(D-159): 모든 컨트롤이 같은 `--accent` 2px(전역 `:focus-visible`). 목록·줄 안쪽은 안쪽으로 2px.
- **목록 행**: 높이 32px, 호버 시 `--surface-hover`, 선택 시 왼쪽 2px `--accent` 막대. 긴 이름은 끝을(파일 경로는 앞을) 말줄임하고 잘렸을 때만 툴팁으로 전체.
- **고친 파일 줄**(r-home.png, D-142, D-143): 두 줄 행(52px). 왼쪽 체크, 위 줄 파일 이름(코드 글꼴 14px), 아래 줄 폴더(`--text-muted` 13px, 앞 말줄임), 오른쪽 상태 글자("새 파일"·"고침"·"삭제", 색과 글자). 넣은 파일이 0개면 모든 체크가 켜진 모양이고 하나를 끄면 나머지가 들어간다. 오른쪽 클릭 메뉴는 "경로 복사"·"이 파일 고친 것 버리기".
- **불러오는 표시**: 300ms가 넘을 때만 보인다.
- **상태 표시**: 색만으로 알리지 않고 글자나 기호를 함께 쓴다(추가 `+`, 삭제 `−`, 파일 상태 이름).
- **빈 상태**: 그림 대신 한 줄 설명과 버튼 하나, 왼쪽 정렬.
- **굵은 글자 버튼**: 테두리 없이 600 굵기. 옆에 단축키를 `--text-muted` 12px 코드 글꼴로(시작 화면 상단 바의 "폴더 열기 Ctrl+O", D-033).
- **버전 이름 칸**: 파일 목록 위에 테두리 없는 큰 글자(600)로 이름, 바로 아래 설명(D-044). placeholder는 제안 이름과 "설명 추가"(`--text-muted`). 포커스는 `--accent` 밑줄 2px. 오른쪽 아래에 옅은 `Ctrl+Enter`와 주 버튼.
- **토스트**: 바로 한 일의 결과를 화면 아래 가운데에 8초 띄운다(D-042). 주 버튼과 같은 `--primary` 바탕에 `--primary-text` 글자(r-saved.png), 떠 있는 그림자. 결과 문구 + 굵은 글자 버튼("되돌리기") + 옅은 단축키. 마우스를 올리면 멈춘다. 한 번에 하나.
- **오류 토스트**(D-166): 성공 토스트와 다른 모양(`--surface` 판, 왼쪽 2px `--deleted` 막대의 오류 알림, `role="alert"`). 닫을 때까지 남고, 쉬운 말 한 줄·해결 버튼 하나(있으면)·접힌 "자세히 보기"(Git 원문)와 오른쪽 위 글자 버튼 "닫기".
- **홈 노선도**(D-046, D-060): 상단 바 아래 두 줄. 위가 기본 브랜치, 아래가 지금 브랜치이고 갈라진 곳에서 꺾인다. 지금 브랜치가 기본 브랜치이거나 갈라지지 않았으면 한 줄. 선 굵기는 기본 브랜치 3, 지금 브랜치 4. 역은 `--surface`로 채우고 브랜치 색 테두리, 지금 버전 역만 크게. "지금 여기"는 `--primary` 바탕 작은 이름표이고 합치기 제안 블록 앞까지 폭을 다 쓴다. 역은 5개까지, 간격은 이름표 폭에 맞춰 넓히고 호버·포커스에 전체 이름 툴팁. 앞쪽이 접히면 왼쪽 끝 24px `--border-strong` 점선과 그 아래 `--text-muted` 글자 버튼 "이전 N개"(누르면 버전 기록, D-141, D-155). 줄 옆 글자(브랜치 이름, 고친 파일 수)는 `--text`·`--text-muted`. 그리기는 버전 기록 그리기 계층의 `layout`·`SvgRenderer`를 쓴다(architecture.md).
- **버전 기록 노선도**(r-log.png, D-087~D-092): 창 전체 폭 목록, 행 48px, 아래 `--border` 1px 선. 왼쪽 그래프 칸(레인 간격 24px, 첫 레인 x 40, 폭 240px까지) 오른쪽에 이름(`--text`, 말줄임) 옆으로 옅은 " · 안 올림"·" · 태그"·" · ● 브랜치"(12px `--text-muted`, 점만 브랜치 색), 작성자 90px, 날짜 90px 오른쪽 정렬, 오른쪽 여백 32px. 고른 행은 `--surface-hover` 바탕(r-log). 역은 `--surface` 채움에 레인 색 테두리, 합치기 버전은 큰 점, 지금 위치는 `--text` 바깥 고리, 접힌 구간은 작은 마름모와 "버전 N개 · 펼치기"(`--text-muted`). 목록 자체가 포커스를 받고(포커스 표시는 안쪽 `--accent` 2px) 고대비에서는 선·점이 `CanvasText`. 여러 역 선택(D-106): Shift+↑↓·Shift+클릭으로 지금 브랜치 선 위의 이어진 구간만 고른다(곁가지 행은 건너뜀). 고른 구간의 행은 `--surface-hover` 바탕과 왼쪽 2px `--accent` 막대, 글자 선택으로 번지지 않는다. 기록 정리할 수 있는 구간(모든 버전 보기, 2~50개, 합친 버전·첫 버전 없음)이면 머리에 글자 버튼 "N개 선택 · 기록 정리". - **GitHub 연결 패널**(D-121): 설정의 GitHub 구역 안. `--surface-sunken` 판(`--radius-panel`, 안쪽 16px)에 연결 코드(코드 글꼴 26px 600, 통째로 선택됨)와 글자 버튼 "복사"("복사했어요"로 바뀜), 아래 `--text-muted` 12px "브라우저에서 코드를 입력해 주세요 · 14:32"(남은 시간이 1초마다 줆), 글자 버튼 "취소". 만료·거절은 `--text-muted` 한 줄과 테두리 버튼 "다시 시도", 오류는 `ErrorNotice`. 연결 중에는 "GitHub 연결"이 꺼진다. 연결되면 토스트 "GitHub에 연결했어요"(되돌리기 없음).
- **복제 대화상자**(D-115, 그림 없음, 이름 대화상자와 같은 판): 폭 560px, 제목 `<Term clone>`. 위에서부터 "주소" 입력칸(코드 글꼴, 포커스가 바로 감, placeholder `https://github.com/이름/저장소`, 붙여넣으면 앞뒤 공백을 뗌), "저장할 곳" 줄(부모 폴더 경로를 코드 글꼴 12px로, 길면 앞쪽을 줄임, 글자 버튼 "바꾸기"), "폴더 이름" 입력칸(주소에서 제안, 고치면 고정), 그 아래 `--text-muted` 12px 결과 경로. Git이 보안 기준보다 낮으면 체크 상자 "Git이 오래됐어요 · 그래도 복제"(켜야 주 버튼이 켜짐). 오른쪽 아래 글자 버튼 "닫기"와 주 버튼 `<Term clone>`(Enter도, 한글 조합 중 무시). 도는 동안 왼쪽 아래 `--text-muted` 12px "복제 중 · N초", 3초 뒤 글자 버튼 "취소", 입력과 닫기는 꺼진다. 오류는 대화상자 안 `ErrorNotice`(로그인 실패·저장소 없음이고 GitHub에 연결 안 됐으면 테두리 버튼 "GitHub 연결"). 성공하면 닫고 프로젝트 열기로 연다(토스트 없음). 시작 화면 상단 바 오른쪽 굵은 글자 버튼 `<Term clone>` + `Ctrl+Shift+O`, 어디서나 같은 단축키.
- **검토 요청 화면**(D-112, 그림 없음, 작업 내역과 같은 느낌): 창 전체 폭. 머리(56px, 아래 `--border`): `<Term pr>`(15px 600), 글자 버튼 "열림 · 닫힘 · 전체"(고른 것은 600, `aria-pressed`), 오른쪽 `소유자/이름`(코드 글꼴 12px `--text-muted`). 준비 안 됨이면 `--text-muted` 한 줄, 미연결이면 빈 상태 "GitHub에 연결하면 검토 요청을 볼 수 있어요"와 주 버튼 "GitHub 연결". 줄(56px 이상, 아래 `--border`): 위 줄 `#12`(코드 12px `--text-muted`) · 제목(`--text`, 말줄임, `<bdi>`) · 상태 글자("열림"·`<Term pr-draft>`·"합쳐짐"·"닫힘", `--text-muted`), 아래 줄(12px `--text-muted`) `feature → main`(코드 글꼴, 포크는 `소유자:feature`) · 작성자 · 날짜 · 지금 브랜치의 요청이면 `--text` "지금 브랜치". 고른 줄은 왼쪽 2px `--accent` 막대와 `--surface-hover`이고 그 아래로 `<Term checks>` "성공 N · 실패 N · 진행 N"(볼 수 없으면 줄 없음), "겹침 있음"(`--deleted` 12px)·"뒤처짐"·"막힘", 글자 버튼 "GitHub에서 열기". 맨 아래 글자 버튼 "더 보기". 목록은 ↑↓로 고르고 Esc는 홈. 상단 바 오른쪽 순서는 동기화 · 검토 요청 · 버전 기록 · 작업 내역 · 설정이고, "검토 요청"은 지금 브랜치가 올리는 원격이 github.com이고 합치는 중이 아닐 때만 보인다(켜져 있으면 600).
- **새 검토 요청 대화상자**(D-113, 그림 없음, 버전 이름 칸과 같은 느낌): 폭 560px, 제목 "새 검토 요청", 부제 `feature → main`. 테두리 없는 큰 제목 칸(15px 600, 포커스는 `--accent` 밑줄 2px, 값은 제안 제목), 본문 글상자(높이 160px, placeholder "설명 추가"), 한 줄에 "대상 브랜치" `select`(코드 글꼴)와 체크 상자 `<Term pr-draft>`. 아래 `--text-muted` 12px "main보다 앞선 버전 N개 · 올리기하지 않은 버전 M개"(차이가 없으면 "main 브랜치와 같아요"와 꺼진 만들기). 이미 열린 요청이 있으면 "검토 요청 #N이 이미 있어요"와 글자 버튼 "GitHub에서 열기"만, 만들기는 꺼진다. 오른쪽 아래 글자 버튼 "닫기"와 주 버튼 "검토 요청 만들기"(Ctrl+Enter도). 올리지 않은 버전이 있으면 먼저 기존 올리기를 하고("올리기 중 · N초", 3초 뒤 "취소") 끝나면 만든다. 성공하면 닫고 토스트 "검토 요청을 만들었어요" + 글자 버튼 "열기"(되돌리기 없음). 오류는 대화상자 안 `ErrorNotice`(연결이 끊겼으면 "다시 연결"). 검토 요청 화면 머리 오른쪽 주 버튼 "새 검토 요청"(지금 브랜치가 기본 브랜치가 아닐 때)과 브랜치 목록이 연다.
- **흐린 줄**: 투명도를 쓰지 않고 글자를 `--text-muted`로 바꾼다(대비 테스트가 투명도를 계산하지 못한다).
- **움직임**: 150ms ease-out, 페이드와 4px 이동만. `prefers-reduced-motion`이면 끈다.

## 문구 (D-027, D-024)
- 괄호로 덧붙이는 설명을 쓰지 않는다. 예: "합치기 그만두기 (원래대로)" → "합치기 그만두기".
- 버튼은 한 가지 동작을 동사로 끝나는 짧은 말로 쓴다. 목적어는 붙여도 된다(예: "폴더 열기").
- 보충 설명은 `<Term>` 툴팁, 일반 툴팁, 또는 둘째 줄로 보여준다.
- 존댓말 해요체로 통일한다. 합쇼체("~합니다")를 섞지 않는다.
- 한 낱말은 한 기능에만 쓴다. 예: "가져오기"는 pull에만, "원격 확인"은 fetch에만(D-059).
- 용어 호버 설명은 동작이면 "~하기", 대상이면 명사로 끝낸다. "~않음·~함·~사라짐" 같은 메모체를 쓰지 않는다. 주의할 내용은 둘째 문장에 "~요"로 쓴다.
- `src/messages/copy-rules.test.ts`가 괄호, 옛 용어, 합쇼체를 확인한다.

## 시작 화면 색 (D-031)
- 큰 노선도("마지막으로 하던 곳")의 선과 점만 브랜치 색(`--graph-*`). 노선도 옆 글자("지금 여기", 브랜치 이름, 버전 이름)는 `--text`·`--text-muted`로 쓴다(다크에서 그래프 색은 글자 대비에 못 미친다).
- 작은 노선도(목록 줄)는 `--border-strong`, 갈라진 브랜치만 `--text-muted`. 이름 칸(200px)과 상태 사이에 240×28px, 선 2px, 역 반지름 3.5.
- 큰 노선도는 높이 104px, 너비는 칸 너비(1100px까지), 기본 브랜치 줄이 아래(y 76)·갈라진 줄이 위(y 36), 역 이름은 갈라진 줄 위, "지금 여기"는 끝 역 아래. 모자라면 오래된 역을 접고 왼쪽 끝 점선과 "이전 N개" 글자로 보인다(홈과 같은 배치 함수, D-090, D-141).
- 상태 글자는 `--text`이고 충돌만 `--deleted`.

## 다크 모드
시스템 설정을 따르고 설정 "화면 모드"에서 시스템 따라가기·라이트·다크를 고른다(D-145, D-151). 고르는 즉시 루트 `data-theme`이 바뀐다. Ubuntu 22.04의 웹뷰가 OS 다크를 못 볼 때는 앱이 GNOME 설정을 읽어 정한다. 토큰만 바꾸고 부품 코드는 같다.

## 확인 사항
- Windows(WebView2)와 Ubuntu(WebKitGTK)에서 글꼴 렌더링과 스크롤바 모양을 매번 비교한다. 스크롤바는 CSS로 얇게 통일.
- 한글 입력: 버전 저장 메시지 입력창에서 조합 중 Enter가 저장을 실행하지 않게 `isComposing`을 확인한다.
- Windows 고대비(WebView2의 `forced-colors: active`)에서 주 버튼·체크 상자가 보이는지 확인한다. WebKitGTK는 GTK 고대비 테마를 웹 내용에 적용하지 않는다.
