# 제품 명세 (Spec)

## 한 줄 요약
Git을 모르는 사람도 프로젝트 폴더를 열고 버튼 몇 번으로 버전 저장·브랜치·합치기·되돌리기·검토 요청을 할 수 있는 데스크톱 앱. Windows와 Ubuntu에서 동작한다.

## 사용자
- **주 사용자**: 코드를 다루지만 Git이 낯선 사람(비전공 개발자, 디자이너, 기획자, 학생).
- **보조 사용자**: Git을 알지만 명령어 대신 빠르고 안전한 화면을 원하는 개발자.

## 원칙
1. **쉬운 말이 먼저, 원래 이름은 호버로.** 모든 Git 용어는 쉬운 이름으로 보이고, 마우스를 올리면 원래 이름·명령·설명이 뜬다(D-006).
2. **망쳐도 돌아올 수 있다.** 위험한 작업은 백업 → 실행 → "방금 작업 취소" 순서. 백업으로도 살릴 수 없는 일만 실행 전에 묻는다(D-042, D-043).
3. **지금 상태가 항상 보인다.** 현재 브랜치, 버전으로 저장하지 않은 변경 수, 올리지 않은 버전 수, 가져올 버전 수를 상단 바와 탭에 늘 표시한다.
4. **그림으로 보여준다.** 브랜치와 합치기는 선과 점으로 그린다. 끌어놓기로 합치기·이 버전만 복사하기·순서 바꾸기가 된다.
5. **담백하게.** 장식 없는 무채색 화면. 색은 브랜치 선·파일 상태·위험 작업처럼 뜻이 있을 때만 쓴다(`docs/design.md`, D-026).

### 충돌 해결 화면 (반복 2, D-028, D-069, D-086)
화면이 묻는 질문은 하나다: "두 브랜치가 같은 줄을 다르게 고쳤어요. 어느 쪽을 남길까요?"

합치는 중(`MERGE_HEAD`)이거나 앱이 시작한 맡겨 둔 파일 꺼내기가 겹쳤으면 홈 대신 이 화면이 열린다. 앱을 껐다 켜도 상태는 저장소에 있으므로 다시 열린다. 고른 것은 git에 쓰지 않고 이 기기에 남겨 두었다가(같은 합치기면 껐다 켜도 이어진다) "마치기" 때 한 번에 쓴다.

원칙
1. 위아래 카드 두 장에 이름표를 단다. "내 브랜치 · 사람 · 날짜 · 메시지", "합칠 브랜치 · 사람 · 날짜 · 메시지". 맡겨 둔 파일을 꺼내는 중이면 합칠 쪽 이름표는 "맡겨 둔 파일".
2. 한 번에 한 곳만 묻는다. "충돌 3곳 중 2곳 남음", 이전·다음 이동, 파일 목록에 끝난 곳 ✓와 남은 곳 ●, 아래 "문제없이 합쳐진 N개".
3. 고르면 아래 "저장될 모습"이 바로 바뀐다. "둘 다 쓰기"는 내 쪽 다음 합칠 쪽.
4. `<<<<<<<`·`=======`·`>>>>>>>` 같은 표시 문자는 어디에도 보이지 않는다. "직접 고치기"도 표시 문자 없는 깨끗한 편집 칸이다.
5. "합치기 그만두기"가 늘 보인다(`git merge --abort`). 위험도 `normal`, 되돌릴 것이 없다. 그만두기 전에 충돌 파일의 지금 내용을 백업 ref로 남긴다(D-070). 맡겨 둔 파일을 꺼내는 중이면 "꺼내기 그만두기"로 꺼내기 전으로 돌아가고 맡겨 둔 파일은 그대로다(D-083).
6. 고치기 전 원래 코드는 "고치기 전 원래 코드 보기"로 접어 둔다. 툴팁에 원래 이름 base.
7. 모든 곳을 고르면 주 버튼 "합치기 마치기"가 나타나고 포커스가 간다. 마치면 합친 버전이 생기고 Ctrl+Z로 합치기 전으로 돌아간다(D-070). 맡겨 둔 파일은 "꺼내기 마치기"로 고친 파일이 된다.
8. 세 쪽이 모두 1MB 이하 텍스트인 파일만 곳마다 묻는다. 이진·한쪽 삭제·링크·큰 파일·모드·서브모듈 충돌은 각 쪽 상태와 앞부분을 보여 주고 파일 단위로 "이걸로"만 고른다(D-086).
9. 단축키: 1·2·3(내 브랜치·합칠 브랜치·둘 다), Ctrl+↑↓(이전·다음 곳). 직접 고치기 칸에서는 받지 않는다. 합치는 중에는 동기화·브랜치 목록·버전 기록·작업 내역 단축키를 끈다.

색 규칙
- 이 화면에서 색은 브랜치를 뜻할 때만 쓴다. 내 브랜치는 `--graph-2`(초록), 합칠 브랜치는 `--graph-1`(파랑).
- 카드 왼쪽 띠, 코드 바탕, "저장될 모습"의 줄 바탕이 고른 쪽 색을 따른다.
- 고른 카드의 "이걸로" 버튼은 `--primary` 채움, 고르지 않은 카드는 흐리게.
- 진행 표시 ✓·●와 선택 막대는 먹색(`--text`). `--accent`는 이 화면에서 쓰지 않는다.
- 두 색은 브랜치 색 함수(`branchColor`)의 예외로 고정한다(D-086).

용어
- "내 브랜치"(ours), "합칠 브랜치"(theirs), "고치기 전 원래 코드"(base). 호버하면 원래 이름. 앱이 시작한 복사·되돌리기·기록 정리의 충돌도 이 화면에서 푼다(반복 3, D-101): 복사는 "내 브랜치"·"복사할 버전", 되돌리기는 "내 브랜치"·"되돌린 모습", 기록 정리는 "옮기는 버전"·"앞서 정리한 기록"이고 단추는 "복사 마치기"·"되돌리기 마치기"·"기록 정리 마치기"(그만두기도 같은 꼴). 기록 정리는 Git의 ours/theirs 뜻이 뒤바뀌므로 core가 쪽을 뒤집어 화면의 뜻을 유지하고, 마친 뒤 다음 버전에서 다시 겹치면 다음 충돌이 이어 열린다. 다른 도구가 시작한 리베이스·cherry-pick·revert는 안내 줄만 보인다(D-086).

## 진입점
D-032·D-033(계획 003). 프로젝트를 여는 모든 진입점은 core의 한 함수를 거친다.
- 앱을 켜면 마지막으로 연 프로젝트를 바로 연다. 연 프로젝트가 없거나, 마지막 프로젝트 폴더가 사라졌거나, 더 이상 Git 저장소가 아니면 시작 화면을 보여주고 맨 위 한 줄로 까닭을 알린다. 다른 프로젝트를 대신 열지 않는다.
- 시작 화면은 작업 공간 상단 바의 프로젝트 메뉴 "다른 프로젝트 열기"로 온다.
- 시작 화면 상단 바의 "폴더 열기"(Ctrl+O). 작업 공간에서도 Ctrl+O로 연다. "복제"(Ctrl+Shift+O, 시작 화면과 작업 공간)는 주소와 저장할 곳을 받아 받은 뒤 그 프로젝트를 연다(D-115).
- 시작 화면 창에 폴더를 끌어다 놓아 열기는 나중에 넣는다(앱 안 끌어놓기 방식을 노선도 반복에서 정한 뒤).
- 폴더 우클릭 메뉴 "Git으로 관리": Windows 탐색기, Ubuntu Nautilus. 시작 화면을 건너뛰고 그 폴더를 연다.
- 명령줄: `higit <폴더경로>`. 이미 실행 중이면 그 창에서 연다(단일 인스턴스). 시작 화면을 건너뛴다.
- 폴더가 Git 저장소가 아니면 "이 폴더는 아직 버전 관리를 하지 않아요"와 "버전 관리 시작"을 보여준다. 둘째 줄에 파일은 그대로 두고 기록만 시작한다고 적는다. 이 안내는 시작 화면 위쪽에 둔다.

위험도:
- `safe`: 바로 실행.
- `normal`: 바로 실행, 실패 시 쉬운 말로 이유와 해결 버튼.
- `caution`: 미리보기 없이 바로 실행. 실행기가 실행 전에 백업 ref와 작업 목록(journal)을 남기고, 아래 토스트로 되돌리기(D-042, D-043).
- `danger`: `caution`과 같다. 올린 기록을 바꾸는 일은 거절하고 되돌리기(revert)를 권한다(D-097). 덮어쓰며 올리기는 설정 화면이 생길 때 넣는다.
- 실행 전 확인은 위험도가 아니라 되돌릴 수 있는지로 정한다. journal과 백업 ref로도 살릴 수 없는 일(덮어쓰며 올리기, 고친 것 버리기, 멈춘 작업 정리, 올린 버전 지우기)만 묻는다(D-043, D-074, D-081). 오래 걸리는 저장·합치기를 강제로 멈출 때도 묻는다(D-080).

## 오류 메시지 원칙
- Git 원문 오류를 숨기지 않되 접어둔다("자세히 보기").
- 먼저 쉬운 말로 무슨 일인지, 그다음 할 수 있는 버튼 1~2개.
  - 예: "올리기 전에 원격 저장소의 새 버전을 먼저 가져와야 해요. [가져오기]"
