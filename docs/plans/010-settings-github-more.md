## 목표
처음 켜면 이름·이메일을 정하고(Git 전역 설정, 사용자가 저장을 누를 때만) GitHub도 이어서 연결할 수 있다. 설정에서 "올린 버전도 바꾸기"를 켜면 올린 버전의 기록도 고치고 덮어쓰며 올릴 수 있고(항상 확인), 원격 브랜치를 지우고 이름을 바꾸고(확인), 태그를 올린다. GitHub에 연결하면 로컬 프로젝트를 새 저장소로 올리고, 복제할 때 내 저장소 목록에서 고르고, 검토 요청 상세에서 리뷰 결과·댓글 수를 보고, 워크플로 파일을 올릴 권한을 선택해서 더한다.

## 현재 상태
이 계획이 기대는 사실만 적는다(코드로 확인).
- 등록 액션 32개. `Executor::execute`는 `Irreversible`이면 미리보기 토큰이 있어야 하고(`take_ticket`이 같은 액션·입력·폴더인지 확인), `risk >= Caution && moves_head()`면 HEAD를 백업한다. `Irreversible`은 journal에 경계 줄을 남기고(`is_barrier`), 결과의 `journal_mode()`가 `Skip`이면 남기지 않는다. `discard`·`clear-lock`만 `Irreversible`이고 `discard`는 스스로 백업 ref를 남긴다. 화면의 확인 창은 `CompareFooter.tsx`(`previewAction` → 토큰 → `executeAction(…, token)`, 포커스는 안전한 "닫기")와 `StuckNotice.tsx`에 제각각 있고 공용 틀은 없다.
- `features/history/menu/items.test.ts`가 "역 메뉴 `actionId`는 `irreversible`이 아니다"를 확인하는 가드 테스트다(008 C11 ⑤). 역 메뉴 항목 중 올린 버전 때문에 흐려지는 것은 `info.unpushed`·`env.upstream`을 본다(`amend`는 `whyPublished`).
- 올림 검사는 `guard::refuse_published`(reset·`undo/run.rs`의 다시 하기)·`guard::is_published`(amend)·`rewrite_chain`의 `Published` 막힘, 세 곳에 `PublishedHistory`로 있고 인자로 정책을 받지 않는다. `ExecCtx { git, state, key, github }`.
- 원격 쓰기는 `GitOp::Push { target, set_upstream, auth }` 하나뿐이고 명령은 `push --progress --no-follow-tags --no-recurse-submodules --no-signed [-u] --end-of-options <원격> HEAD:refs/heads/<브랜치>`다. 모든 원격 호출은 `run_network(repo, args, mode, auth)`를 거친다. `actions/remote.rs`의 `upstream`·`pick_remote`·`Net`·`push`는 모듈 안 전용이다. `REMOTE_ACTIONS = [fetch, pull, push, sync, clone]`(`pr-create`는 HTTP 하나라 없음, D-123). 잠금은 `fetch`·`push`·`pr-create`가 원격만, `pull`·`sync`·`clear-lock`이 둘 다.
- 실패 분류 `failure.rs`는 `HttpForbidden`·`RemoteNotFound`·`GithubWorkflowScope`를 `PushRejected`("[rejected]") 앞에 두고, 일반 "already exists"는 `BranchExists`다. "(stale info)"·"[remote rejected]"·"(already exists)"(태그)·"remote ref does not exist"는 따로 가르지 않는다.
- 이름·이메일은 `has_identity`(`git var GIT_COMMITTER_IDENT`)로만 알고 `IdentityMissing` 오류 문구 한 줄이 있다. 쓰기는 없다. `GitBackend`에 저장소 없이 도는 쓰기는 없고(`Init`·`Clone`은 폴더를 `repo` 자리에 넘김), `global_ssh_command`가 `--global`·`--system`을 따로 읽는 선례다. 테스트 백엔드는 `CliBackend::new("git", Arc::new(isolate))`(명령마다 환경을 고치는 훅)이라 시험이 전역 설정 파일 경로를 따로 줄 수 있다. 앱 데이터에는 `recent.json`·`trust.json`·`github.json`이 있고 `settings.json`은 없다.
- 설정 대화상자는 "GitHub" 구역 하나(`SettingsDialog`·`GitHubSection`·`ConnectPanel`, `settingsStore.openSettings(connect?)`). 시작 화면은 최근 프로젝트가 없으면 `✓ Git … 찾았어요` 한 줄만 보인다. 브랜치 목록 줄의 `…` 메뉴(이름 바꾸기·지우기)는 로컬 줄에만 있다. `TagDialog`는 태그 만들기와 줄마다 "지우기"만 있다. `CloneDialog`는 주소를 붙여 넣는다.
- hosting: `HostingProvider`(`begin_login()`은 설정의 `scope` 문자열 `repo`를 쓰고 `LoginPoll::Granted(SecretString)`은 받은 권한을 버린다), `github.json`은 `{ v, login, id }`, `GitHubStatusView { configured, connected, login, remembered }`, `HostingPage = DeviceLogin | AppSettings | PullRequest`. `pr_detail`은 `pulls/{n}`과 `check-runs`만 부른다. 저장소 만들기·목록·리뷰는 없다. 오류 → `ErrorCode` 변환은 `github::from_hosting` 한 곳이고 `Validation(AlreadyExists)`는 `PrAlreadyExists`로 간다.
- Git 최소 버전 2.30, `git-min`(Ubuntu 22.04 컨테이너)은 2.34.1. 새 git 명령과 `--force-with-lease=<ref>:<값>`·`--end-of-options`는 `git-min`에서 확인한다.

## 완료 기준 (반복 전체)
두 OS(Ubuntu 22.04 git 2.34.1, Windows 11)에서 손으로, 가능한 것은 자동 테스트로 확인한다. 실제 GitHub 계정이 필요한 것은 `docs/progress.md` "사람이 할 일"이다.
- 이름·이메일: 전역 설정이 비어 있고 최근 프로젝트가 없으면 시작 화면에 start-first.png 모양의 패널이 보이고, 이름·이메일을 저장하면 `git config --global --get user.name`·`user.email`이 그 값이며 패널이 사라진다. 저장하기 전에는 전역 설정 파일이 바뀌지 않는다. 설정 "이름과 이메일" 구역에서 고칠 수 있고, 버전 저장이 이름 없음으로 실패하면 오류 줄 단추가 설정을 연다. 시험은 `GIT_CONFIG_GLOBAL`을 임시 파일로 돌려 사용자 파일을 건드리지 않는다.
- 설정 "고급 → 올린 버전도 바꾸기"가 기본 꺼짐이고 `settings.json`에 저장된다. 꺼져 있으면 지금처럼 `PublishedHistory`로 거절된다. 켜면 올린 버전에도 마지막 버전 고치기·이 버전으로 돌아가기·기록 정리·그 다시 하기가 된다.
- 덮어쓰며 올리기: 스위치가 꺼져 있으면 보이지 않고 core도 거절한다. 켜면 역 메뉴 "더 보기"와 알림 줄에서 확인 창이 뜨고, 사라지는 버전 수·다른 사람의 버전 수가 보이고, 기본 브랜치는 거절되고, 덮어쓸 것이 없으면 거절되며, 확인하면 `--force-with-lease=<보여 준 해시>`로만 올라가고 원격 옛 끝이 백업 ref에 남는다. 그사이 원격이 바뀌면 거절된다. 확인 토큰 없이 실행하면 `PreviewRequired`다.
- 올린 기록을 바꾼 뒤 갈라진 상태에서 동기화하면 합치지 않고 `RewrotePublished` 알림 줄이 뜨고, [덮어쓰며 올리기]·[그래도 합치기]가 각각 동작한다. 평범하게 갈라진 경우(내 기록을 바꾼 흔적 없음)는 지금처럼 합친다.
- 원격 브랜치: 브랜치 목록의 원격 줄 `…`에서 지우기·이름 바꾸기가 확인 창을 거쳐 되고, 원격 기본 브랜치·`HEAD`는 거절되고, 이름 바꾸기는 같은 이름이 원격에 있으면 거절되며 로컬 브랜치의 upstream이 새 이름으로 이어진다. 둘 다 확인 토큰이 필요하고 백업 ref가 남는다.
- 태그 올리기: 역 메뉴 태그 대화상자의 "올리기"가 그 태그만 올리고, 같은 이름·다른 버전이 원격에 있으면 덮어쓰지 않고 오류를 알린다.
- GitHub에 올리기: 원격이 없는 프로젝트에서 연결돼 있으면 상단 바에 "GitHub에 올리기"가 보이고, 대화상자에서 이름·설명·공개 여부(기본 비공개)로 저장소를 만들고 `origin`을 잇고 이어서 올린다. 이름이 있으면 안내되고, 원격이 이미 있으면 거절된다. 가짜 GitHub로 자동 시험, 실제 계정은 손 확인.
- 복제 대화상자의 "내 저장소"가 연결됐을 때 목록(50개씩)을 보이고 고르면 주소가 채워진다. 검토 요청 상세에 "리뷰 승인 N · 변경 요청 N"과 "댓글 N"이 보인다. 연결 상태에서 "워크플로 권한 추가"가 `repo workflow`로 다시 연결하고 `GithubWorkflowScope` 오류가 같은 단추를 보인다.
- 새 액션 6개의 위험도가 용어표와 같다(`registry-glossary`). `Irreversible` 액션은 정확히 `{discard, clear-lock, force-push, remote-branch-delete, remote-branch-rename}`다. 새 용어 6개가 표·glossary ko·en에 있다. 새 오류 코드마다 ko·en 문구가 있다(완전성 테스트). 새 명령 7개가 네 곳에 있다(`tests/security_config.rs`).
- 토큰·`device_code`는 어떤 새 화면 타입·로그·오류·명령줄·주소에도 없다. 이름·이메일은 로그·토스트·오류에 없다.
- 800px 너비와 다크 모드에서 처음 실행 패널·설정·확인 창·올리기 대화상자·복제 목록이 겹치거나 잘리지 않는다(긴 이름·주소는 말줄임).
- `pnpm check:full`, 두 OS CI(`git-min` 포함)·`cargo deny check` 통과. code-analyst 점검 위반 0건.

## 단계
각 단계 = 커밋 하나, 메시지는 `<영역>: <요약>`(아래 제안). Rust를 고친 단계는 커밋 전에 `pnpm check:full`. `core::view`·Tauri 명령·액션 목록이 바뀌면 같은 커밋에서 `cargo run -p app --bin gen-bindings`. 새 Tauri 명령은 `src/commands.rs`·`src/bindings.rs`·`build.rs`의 `COMMANDS`·`capabilities/default.json` 네 곳과 `src/lib/api.ts`를 같은 커밋에 넣는다(`tests/security_config.rs`가 확인). 새 액션은 architecture.md "새 액션 추가 절차"대로: spec 용어표·glossary(H1) → `GitOp`(git 단계) → `ActionInput`·`actions/<id>.rs`·`register_all`·`Outcome`/`ActionResult` → 화면 → 테스트(임시 저장소에서 실행 → 결과 → 되돌리기 없음 또는 `Irreversible` 토큰 확인). `GitBackend`에 메서드를 더하면 가짜 구현 둘(`executor.rs` 테스트의 `NoGit`, `crates/core/tests/common/mod.rs`의 `FakeGit`)도 같은 커밋에서 고친다. 새 git 명령은 `args::Cmd` 변형(`--end-of-options`가 2.34.1에서 되는지)을 정하고 `git-min`에서 확인한다. `ExecCtx`에 필드를 더하면 모든 생성부(`bootstrap.rs`·실행기 시험·`tests/common`)를 같은 커밋에서 고친다. 테스트 저장소는 `core.autocrlf false`·`user.name`·`user.email`·`commit.gpgsign false`를 저장소에 넣고 파일 이름에 Windows 금지 글자(`*?:<>|"`)를 쓰지 않는다. **테스트는 사용자 전역 설정·실제 키체인·실제 네트워크를 건드리지 않는다**(전역 설정은 시험마다 임시 `GIT_CONFIG_GLOBAL`을 주는 `isolate` 훅, 원격은 로컬 bare 저장소 + `allow_local_remotes_for_tests`, GitHub는 가짜 `HttpTransport`, 키체인은 모의 저장소). 용어 호버는 `<Term>`, 문장 속 용어는 `t(id)`(D-029). 화면 문구는 `src/messages` ko·en(괄호·옛 용어·합쇼체 없음, `copy-rules`·`terms-in-messages`)에 두고 이름과 숫자만(D-049, 토스트·오류·안내 한 줄은 D-057). 색은 `tokens.css` 변수만. 새 `ErrorCode`는 `messages`의 `errors`에 ko·en 문구를 같은 커밋에(완전성 테스트). 모든 새 화면 입력은 한글 조합 중(`isComposing`, WebKitGTK `keyCode 229`) Enter를 무시한다(`DialogFrame`의 `composing`). **되돌릴 수 없는 액션의 확인 창은 포커스를 안전한 "닫기"에 두고 Enter가 위험 버튼을 누르지 않는다(D-043, `CompareFooter` 방식).** **토큰·device code·이름·이메일은 어떤 단계에서도 로그·토스트·명령줄·주소에 넣지 않는다.**

H3. git: 전역 이름·이메일 읽기·쓰기 (`git: add global identity read and write`)
- 목표: 저장소 밖 전역 설정을 `GitBackend` 뒤에서 읽고 쓴다(C2).

- 내용: `identity()`는 키마다 `git config --global --includes --get <키>`를 읽고 없으면 `--system --includes`(종료 코드 1은 없음, 다른 실패는 오류), cwd 없음, 앞뒤 공백과 개행 제거, 앱 쪽 상한 4KB. `run_global(SetIdentity)`는 `git config --global user.name <값>` 다음 `user.email <값>`(`-`로 시작하는 값은 core가 먼저 거절한다. 그래도 `git-min`에서 값이 옵션으로 읽히지 않는지 시험해, 읽히면 core 검사를 유일한 방어로 적고 그 시험은 "거절 확인"으로 바꾼다). 둘째가 실패하면 첫째는 그대로 두고 오류(되돌리지 않음). `GIT_CONFIG_GLOBAL`·`GIT_CONFIG_NOSYSTEM`은 건드리지 않아 사용자 환경 변수를 그대로 따른다. 쓰기 실패 분류는 기존 `Locked`(".lock': File exists")와 `Other`.
- 테스트(실제 git, 임시 `GIT_CONFIG_GLOBAL` 파일을 주는 훅): 빈 파일에서 읽기(없음), 쓰고 읽기(한글 이름·`+`가 든 이메일), 덮어쓰기, `[include] path`로 가져온 값을 읽음(`--includes` 시험), 시스템 값 폴백(`GIT_CONFIG_SYSTEM`), 값 두 개가 있는 키는 오류로 알림(덮어쓰지 않음), 읽기 전용 파일에 쓰기 실패, 저장소 안 cwd에서 불러도 저장소 로컬 `user.name`이 섞이지 않음, `git-min`.

- Windows/Ubuntu: Ubuntu는 `~/.gitconfig`가 없고 `$XDG_CONFIG_HOME/git/config`가 있으면 거기에 쓴다(git이 정함). Windows는 `%USERPROFILE%\.gitconfig`·경로의 한글·공백·`OneDrive` 리디렉트(git이 정함), CRLF는 git이 처리.

- 바꿀 파일: `types.rs`(`GitOp::PushForce { remote, branch, expect: Oid, auth }`, `PushDelete { remote, branch, expect: Oid, auth }`, `PushNewRef { remote, branch, oid: Oid, auth }`, `PushTag { remote, name, auth }`), `backend.rs`(`ls_remote(&self, repo, remote, refname, auth) -> Result<Option<Oid>>`), 신규 `cli/refpush.rs`(+`refpush_tests.rs`), `cli/args.rs`(`Cmd::LsRemote`), `cli/mod.rs`(`run` 매핑·`ls_remote`), `failure.rs`(+표 테스트), 가짜 구현 둘, `docs/architecture.md`(GitOp 목록, 시간 제한 표).
- 내용: 모두 `run_network(…, Foreground, auth)`. 공통 앞부분은 기존 `Push`와 같다(`push --progress --no-follow-tags --no-recurse-submodules --no-signed`). `PushForce`: `--force-with-lease=refs/heads/<branch>:<expect>` + `--end-of-options <remote> HEAD:refs/heads/<branch>`(`--force`·`+refspec` 금지, 코드에 `--force` 단독이 나오지 않게). `PushDelete`: `--force-with-lease=refs/heads/<branch>:<expect> --end-of-options <remote> :refs/heads/<branch>`. `PushNewRef`: `--force-with-lease=refs/heads/<branch>: --end-of-options <remote> <oid>:refs/heads/<branch>`(빈 값 lease = 원격에 없어야 함, 시험으로 2.34.1에서 확인하고 안 되면 core의 `ls_remote` 확인에만 기댄다). `PushTag`: `--end-of-options <remote> refs/tags/<name>:refs/tags/<name>`(강제 없음). `ls_remote`는 `ls-remote --end-of-options <remote> <refname>`(안 되면 `--`)로 한 줄 `<oid>\t<ref>`만 파싱한다. 이름은 호출한 core가 `check_branch_name`·`check_tag_name`으로 이미 검사한 값이고 `Oid`로만 해시가 닿는다. 새 실패 종류 4개를 `PushRejected` **앞에** 둔다: `LeaseStale`("(stale info)"), `RemoteRefused`("[remote rejected]", "protected branch", "GH006", "refusing to delete the current branch"), `RemoteRefExists`("(already exists)"), `RemoteRefMissing`("remote ref does not exist"). 같은 커밋에서 `ErrorCode`(`RemoteMoved`·`RemoteRefused`·`RemoteRefExists`·`RemoteRefMissing`)·`From` 매핑·ko/en 문구·바인딩을 함께 고쳐 컴파일이 깨지지 않게 한다(009 G8a와 같은 방식).
- 테스트(실제 git, 로컬 bare 원격 + `allow_local_remotes_for_tests`): `PushForce`가 기대 값이 맞을 때 덮어쓰고 틀리면 `LeaseStale`, 기대 값 밖의 다른 브랜치는 그대로, 인자에 `--force` 단독·`+`가 없음(스냅샷), `PushDelete`가 맞으면 지우고 다른 값이면 `LeaseStale`·이미 없으면 `RemoteRefMissing`, `PushNewRef`가 없을 때만 만들고 있으면(앞서가는 값이어도) 거절, `PushTag`가 새 태그는 올리고 같은 이름·다른 버전은 `RemoteRefExists`·같은 버전은 성공, 보호 브랜치를 흉내 낸 `pre-receive` hook 거절이 `RemoteRefused`, `ls_remote`(있음·없음·다른 ref는 안 읽음), `failure.rs` 새 문구 표와 기존 문구가 그대로, 옵션처럼 보이는 이름(`-x`)은 core가 막지만 git도 옵션으로 읽지 않음(`--end-of-options`), `git-min`.
- 완료 기준: `cargo test -p git` 두 OS와 `git-min`, `cargo test --workspace`.
- Windows/Ubuntu: 한글·공백 브랜치 이름의 인자(셸 없음), Windows는 `file://` 대신 로컬 경로 원격 시험이 경로 구분자를 쓰므로 기존 `remote_tests`와 같은 방식, `pre-receive` 시험 hook은 Windows에서 Git for Windows `sh`로 돈다(실패하면 Unix만 시험하고 `#[cfg(unix)]`로 표시).
- 보안: `--force` 단독·강제 refspec이 코드에 없다. 값 있는 lease만. 해시는 `Oid`, 이름은 core가 검사한 것.

## 위험과 열린 질문
- **덮어쓰며 올리기가 남의 작업을 지움**(가장 큼): 대책은 스위치(기본 꺼짐) + 항상 확인 창(사라지는 버전 수·다른 사람의 버전 수·앞 5개) + 확인 토큰이 입력에 묶임 + 값 있는 lease(그사이 올라온 것은 거절) + 기본 브랜치 거절 + 옛 원격 끝의 백업 ref + 경계 줄. 남는 위험: 확인 창을 읽지 않고 누르는 사람, 마지막 `fetch` 이후 올라온 동료 버전은 lease가 막지만 `fetch` 전에 이미 받은 동료 버전은 "사라지는 버전"에 보일 뿐 막지 않는다(그래서 "다른 사람의 버전"을 눈에 띄게). 백업 ref는 30일 뒤 정리된다(D-079).
- **스위치 하나가 두 일을 켬**(올린 기록 바꾸기 + 덮어쓰며 올리기): 둘을 따로 켤 수 있으면 "고쳤는데 올릴 수 없는" 상태가 생겨 오히려 혼란이다. 하나로 두고 설명 한 줄에 둘 다 적는다. 사람들이 이름을 못 알아보면 문구만 고친다(데이터 모델은 그대로).
- **동기화 보호(`rewrote_published`)의 정확도**: journal 서명 키가 이번 실행만의 것이거나 journal이 4MB를 넘어 뒤쪽만 읽히면 흔적을 못 볼 수 있다(그러면 보호 없이 지금처럼 합친다, 거짓 음성). 오탐은 "그래도 합치기"로 풀린다. 시험이 표로 고정하고 손 확인에서 실제 흐름을 본다.
- **전역 git 설정 쓰기**(C2): 사용자 파일을 바꾸는 유일한 앱 기능이다. 눌렀을 때만 쓰고 둘 다 같은 `--global` 파일에 쓴다. 남는 경우: `[include]`로 가져온 값이 있으면 본 파일의 새 값이 이긴다(위치에 따라 달라질 수 있음), `includeIf` 조건부 설정을 쓰는 사람은 읽기가 못 볼 수 있어 패널이 한 번 뜬다("나중에"), 홈이 읽기 전용이면 쓰기 실패("자세히 보기"), 이름만 쓰고 이메일이 실패하면 반쪽 상태(화면이 다시 읽음). 시험은 항상 임시 `GIT_CONFIG_GLOBAL`이다.
- **원격 브랜치 이름 바꾸기의 부분 실패**: 새 이름은 올렸는데 옛 이름 지우기가 실패(권한·보호)하면 둘 다 남는다. 되돌리지 않고 알리며 사용자가 원격 브랜치 지우기로 마무리한다. 원격 기본 브랜치·`HEAD`는 막는다.
- **원격 브랜치 지우기가 열린 검토 요청을 닫음**(GitHub 동작): 확인 창이 열린 요청 번호를 보인다(연결돼 있을 때만, 못 읽으면 줄 없음). 복구는 브랜치를 다시 올리고 GitHub에서 요청을 다시 연다.
- **빈 lease(`--force-with-lease=<ref>:`)의 git 버전 차이**: 2.34.1에서 시험하고, 안 되면 `PushNewRef`는 core의 `ls_remote` 확인에만 기댄다(틈: 확인과 올리기 사이의 경쟁, 같은 이름이면 git이 ff일 때만 갱신하므로 비-ff는 거절됨). H7이 결과로 정한다.
- **GitHub에 올리기**: 만든 저장소는 앱이 지울 수 없다(`delete_repo` 권한 없음, 의도). 공개 선택을 잘못하면 코드가 공개된다(기본 비공개, 선택 줄 안내, 올리기 전에 버전 수 표시). 첫 올리기는 전체 기록을 보내므로 과거 버전에 든 비밀은 이번 반복이 검사하지 않는다(버전 저장 때 파일 검사만, D-077). 키체인을 못 쓰는 환경에서는 올리기가 사용자 git 인증을 따라 실패할 수 있고 저장소는 이미 만들어져 있다(안내 줄 + "다시 올리기"). 조직 정책이 저장소 만들기를 막으면 403.
- **`workflow` 권한**: 한 번 더하면 줄일 수 없다. 앱 권한 페이지 링크와 "연결 끊고 다시 연결"로만 줄인다. 조직의 OAuth 앱 제한은 009 위험 절과 같다.
- **GitHub 서버 가정**: 리뷰 API 응답(상태 이름 `APPROVED` 등)과 `/user/repos` 필드, 저장소 만들기 422 문구("name already exists")는 가짜 응답 표본으로 시험하므로 실제와 어긋나면 손 확인에서 드러난다(문구가 바뀌면 `Invalid`로 떨어져 안내만 덜 구체적이다).
- **설정 대화상자가 커짐**: 구역이 셋이 돼 800px에서 세로로 길어질 수 있다(스크롤, 구역 제목 고정 없음). 그림이 없는 화면이라 처음 모양이 어색하면 `docs/design.md`만 고친다.
- **`ExecCtx.settings` 추가**: 모든 생성부를 한 커밋에서 고쳐야 하는 변경이라 H2가 크다. 가짜 구현·실행기 시험의 생성부를 먼저 찾아(`rg "ExecCtx \{"`) 같은 커밋에 넣는다.
- 구현 중 알게 된 것은 이 문서가 아니라 `docs/progress.md`에 적고, 결정이 필요하면 `docs/decision.md`에 "(자동 결정)"으로 올린 뒤 이어 간다.
- code-analyst 검토 때 먼저 볼 곳: H7·H9(`--force` 단독·빈 lease가 `PushNewRef` 밖에 없는지, 확인 토큰이 `expect_*`에 묶이는지, 백업 실패 시 실행 안 함, 기본 브랜치 거절), H8(`Allow`가 다른 검사를 건너뛰지 않는지, 스위치 값이 화면 인자로 바뀌지 않는지, 동기화 보호의 거짓 음성), H3·H4(전역 설정 쓰기가 `identity-set` 한 곳뿐인지, 값 검사, 로그에 이름·이메일 없음, 시험이 사용자 파일을 안 건드리는지), H11(지울 수 있는 대상이 "추적 ref가 있고 값이 확인된 것"뿐인지, 이름 바꾸기가 기존 이름을 덮어쓰지 않는지), H14·H15(서버가 준 `clone_url`·URL을 쓰지 않는지, 소유자 검사, JSON을 serde로만), H6(확인 창 포커스·Enter), H16(`github.json` 호환·토큰 세대).
- 질문(사람 확인이 필요하면): ① 스위치 이름과 한 스위치로 묶는 것(C4)에 동의하는지. ② 원격 기본 브랜치에는 덮어쓰며 올리기·지우기를 이번 반복에 막는 것(C5·C7)에 동의하는지. ③ "GitHub에 올리기"의 낱말이 `push`("올리기")와 겹치는 것(C13). ④ 리뷰·댓글을 읽기 요약만 넣고 쓰기·포크를 4c로 미루는 것(C1). 사람 확인 없이 진행하는 지시이므로 위 추천안으로 구현하고 `docs/decision.md`에 "(자동 결정)"으로 남긴다.

## 사람이 할 일
`docs/progress.md`의 "사람이 할 일"에 H20에서 옮긴다. **사람만 줄 수 있는 것**은 새로 없다(client id는 반복 4에서 받은 것을 그대로 쓴다). 실제 컴퓨터·계정에서 확인할 것:
- **전역 설정 백업 후 확인**: 이름·이메일 첫 실행 패널(전역 설정이 비어 있는 계정이나 `GIT_CONFIG_GLOBAL`을 빈 파일로 돌려 실행)에서 저장 → `git config --global -l`, 설정에서 고치기, 저장 전에는 파일이 안 바뀌는지, 두 OS(Windows `%USERPROFILE%\.gitconfig`, Ubuntu `~/.gitconfig` 또는 XDG), 한글 이름 IME, 버전 저장 오류 줄 단추, 800px·다크, start-first.png·start-first-dark.png와 모양 비교.
- **일회용 GitHub 저장소(비공개)와 가능하면 두 번째 계정이나 공동 작업자**로 덮어쓰며 올리기: 설정 스위치 켜기 → 올린 버전 고치기·기록 정리 → 알림 줄 → 확인 창의 숫자(다른 사람의 버전 포함 시나리오), 그사이 다른 계정이 올렸을 때 거절되는지, 기본 브랜치가 막히는지, 동기화가 `RewrotePublished`로 멈추는지와 "그래도 합치기".
- **원격 브랜치**: 일회용 저장소에서 이름 바꾸기·지우기, 열린 검토 요청이 닫히는 것과 확인 창에 번호가 뜨는지, 원격 기본 브랜치가 막히는지, 로컬 브랜치 upstream이 새 이름으로 이어지는지. **태그 올리기**: 새 태그, 같은 이름 다른 버전의 거절.
- **GitHub에 올리기**: 원격이 없는 폴더(한글 폴더 이름 포함)에서 비공개로 올리기, 공개 선택 안내, 같은 이름 거절, 올린 뒤 "열기", 키체인이 잠겼을 때(Ubuntu 키링) 올리기 실패 안내와 "다시 올리기", 만든 일회용 저장소는 GitHub 설정에서 직접 지우기.
- **복제 목록**: 연결 상태에서 "내 저장소"(비공개·조직 저장소 포함 여부), 더 보기, 고른 뒤 실제 복제. **검토 요청 상세**: 리뷰 승인·변경 요청·댓글 숫자가 GitHub 화면과 맞는지.
- **`workflow` 권한**: "워크플로 권한 추가"로 다시 연결 → 브라우저에 새 권한이 보이는지 → `.github/workflows/*.yml`이 든 버전 올리기(권한 전에는 `GithubWorkflowScope` 안내, 후에는 성공), 앱 권한 페이지에서 권한 확인.
- **웹뷰**: 확인 창 포커스가 "닫기"에 가는지·Enter가 위험 버튼을 누르지 않는지(WebView2·WebKitGTK), 설정·올리기·이름 바꾸기 입력의 한글 IME(조합 중 Enter), 800px·다크, 원격 줄 `…` 키보드.

## 검토 반영 (code-analyst, 구현 전)
구현은 아래를 위 단계 설명보다 우선한다. 결정 번호는 C1~C14 → D-124~D-137 그대로. git 2.34.1 임시 bare 저장소로 lease·삭제·태그·`ls-remote`·`git config` 동작을 직접 확인한 결과를 담았다.

### 바뀐 결정
- **C5·C7(D-128·D-130) 원격 기본 브랜치 보호는 막는 쪽(fail-closed)으로.** `remote_head`는 `refs/remotes/<원격>/HEAD`가 없으면(직접 `remote add`, `publish`) `None`이라 보호가 빠진다. 보호 대상 = ① 실행 단계에서 `ls-remote --symref <원격> HEAD`(기계용 한 줄 `ref: refs/heads/main\tHEAD`)로 읽은 서버 기본 브랜치, 읽지 못하면 거절 ② 로컬 `refs/remotes/<원격>/HEAD` ③ `main`·`master`와 전역·로컬 `init.defaultBranch` 값은 언제나. 계획 조회(네트워크 없음)는 ②·③으로 막힘을 보이고 실행 때 ①로 다시 본다. "`HEAD`가 아님"은 "원격 브랜치 이름이 `HEAD`인 것(원격 HEAD 별칭)을 다루지 않음"이다.
- **C4(D-127) 보정: 스위치를 켜도 upstream이 원격 기본 브랜치이면 `PublishedRule::Allow`를 적용하지 않는다**(`PublishedHistory` 유지). 그렇지 않으면 `main`에서 올린 버전을 고쳤는데 덮어쓰며 올리기는 막혀 `RewrotePublished`만 남는 막다른 길이 된다. 스위치 설명 한 줄에 "덮어쓰며 올리기도 켜져요"(`t("force-push")`)를 함께 쓴다.
- **C6(D-129) 바꿈: "올린 기록을 바꿨다"는 흔적은 journal이 아니라 전용 서명 표식에 둔다.** journal은 경계 줄(`discard`·`clear-lock`·`ParkedResolved`) 뒤에 이력이 끊기고(`undo/run.rs:67-69`) 50줄이 금방 쌓인다. `core::marker`처럼 git 폴더 실제 경로에 묶고 journal 키로 서명한 `rewrote.json`(브랜치별 `{ branch, upstream, old_tip }`)을 `Allow`로 올린 기록을 바꿀 때(고치기·돌아가기·기록 정리·그 다시 하기) 쓰고, `force-push` 성공·HEAD가 그 upstream 끝의 자손이 됨·브랜치 지우기 때 지운다. 키가 이번 실행만의 것이면 표식을 쓰고 이번 실행 동안 메모리로도 들고 있는다. 보호 범위: `sync`가 **갈라졌을 때와 `ahead == 0, behind > 0`(돌아가기 뒤 `MergeFf`가 옛 버전을 되살림) 둘 다** 표식이 있으면 `RewrotePublished`로 멈춘다. `pull`은 입력이 없어 `merge_anyway`를 받지 못하므로 표식이 있으면 늘 멈추고, "그래도 합치기"는 `sync`(`SyncInput.mergeAnyway`)로만 한다.
- **C9(D-132) 보탬: 공개로 올리기는 한 번 더 묻는다.** 입력의 공개 여부는 기본값 없는 `visibility: Private | Public`(필수 필드)이고, `Public`이면 `acknowledgePublic: true`가 있어야 core가 받는다(아니면 `InvalidInput`). 대화상자는 공개를 고르면 안에서 확인 단계를 보이고 포커스는 안전한 "비공개로 하기"에. 주 버튼 이름은 "저장소 만들고 올리기", 용어 호버에 "새 저장소를 만들고 올려요. 만든 저장소는 앱에서 지울 수 없어요".
- 질문 4개는 추천안대로: ① 스위치 하나 + "올린 버전도 바꾸기"(위 보정 둘), ② 원격 기본 브랜치는 이번 반복에 막음(푸는 안은 4c: 이름 입력 확인 + 서버 보호 규칙 안내), ③ "GitHub에 올리기" 이름 그대로(덮어쓰며 올리기·태그 올리기와 같은 계열, 주 버튼이 두 단계를 드러냄), ④ 리뷰·댓글은 읽기 요약만.
