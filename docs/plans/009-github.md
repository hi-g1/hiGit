## 목표
GitHub 계정을 앱에 연결하고(브라우저 코드 입력, 토큰은 OS 키체인에만), 연결하면 GitHub 비공개 저장소의 동기화·원격 확인이 로그인 창 없이 되며, 검토 요청(PR)을 목록으로 보고 상태를 확인하고 새로 만들 수 있다. 시작 화면의 "복제"(Ctrl+Shift+O)로 주소를 붙여 프로젝트를 받아 오고, GitHub 프로젝트에서는 브랜치 목록이 "main에 합치기"보다 "검토 요청"을 먼저 권한다. GitHub OAuth App의 client id는 사람이 만들어 줄 때까지 비워 둘 수 있고, 비어 있으면 연결이 "준비 안 됨"으로 보일 뿐 앱은 그대로 빌드·테스트·사용된다.

## 범위
- 새 크레이트 구현: `hosting`(트레이트, GitHub 구현, 전송 틀), `platform`(키체인, 앱 실행 파일 위치). 새 의존성은 G2에서 먼저 시험한다.

- core: GitHub 연결 서비스(상태·로그인 흐름·끊기·토큰 읽기), credential helper 응답 함수, 새 액션 2개(`clone`, `pr-create`), 조회(`hosting_context`·`pr_list`·`pr_detail`·`pr_draft`·`clone_defaults`), 새 Tauri 명령 11개.
- 화면: 설정 대화상자(GitHub 연결·끊기만), 복제 대화상자와 시작 화면 "복제"·Ctrl+Shift+O, 검토 요청 화면(상단 "검토 요청"), 새 검토 요청 대화상자, 브랜치 목록의 "검토 요청".

## 현재 상태
이 계획이 기대는 사실만 적는다(코드로 확인).
- `crates/hosting`은 `#![forbid(unsafe_code)]` 한 줄뿐이고 `crates/core/Cargo.toml`은 hosting을 의존하지 않는다. `crates/platform`에는 키체인이 없다(architecture.md OS 표에만 "keyring 크레이트"가 적혀 있다). `architecture.md`의 `HostingProvider`는 `detect`·`auth_status`·`list_prs`·`create_pr` 네 함수의 스케치다.
- 원격 액션 4개(`fetch`·`pull`·`push`·`sync`, `actions/remote.rs`)가 `GitOp::Fetch { remote, background }`·`Push { target, set_upstream }`를 쓰고 둘 다 `CliBackend::run_network(repo, args, NetMode)`로 간다. `run_network`는 `GIT_SSH_COMMAND=ssh -o BatchMode=yes`(사용자가 정하지 않았을 때), 백그라운드는 `credential.interactive=never`·`GCM_INTERACTIVE=never`·askpass 제거를 준다. 실패 분류는 `failure.rs` 한 곳이고 `HttpAuthFailed`·`SshAuthFailed`·`RemoteUnreachable`이 있다. 403·404·"workflow scope" 문구는 따로 가르지 않는다(`unable to access`가 `RemoteUnreachable`로 잡힌다).
- 등록 액션 30개(`actions::register_all`). `Core::execute`는 액션 id로 잠금을 고르고(`fetch`·`push` = 원격 잠금, `pull`·`sync`·`clear-lock` = 둘 다), `REMOTE_ACTIONS = [fetch, pull, push, sync]`는 언제든 취소할 수 있다. `tracked`(진행 알림·취소 표시)는 `state.repo`가 있을 때만 걸고, `Running`·`cancel_flag`는 저장소 경로 하나로 키를 쓴다. `with_locks_by`와 `state_of`는 `project_open`을 거친 폴더만 받는다(`opened.require`). `init`의 `Outcome::RepoCreated`는 `Core::execute`가 열린 목록·최근 목록에 넣는다.
- `ExecCtx { git, state, key }`, `Queries::new(git, opened, recent, trust, key)`. `GitBackend`의 가짜 구현이 둘이다(`executor.rs` 테스트의 `NoGit`, `crates/core/tests/common/mod.rs`의 `FakeGit`).
- 화면: `shortcuts.ts`의 `PLANNED`에 `Ctrl+Shift+O`("반복 4: 복제")가 있고 `Start.tsx` 상단 바에는 "폴더 열기 Ctrl+O"만 있다. `TopBar.tsx` 오른쪽은 동기화·버전 기록·작업 내역(≤5개 규칙). `WorkspaceView = "home" | "history" | "activity" | "rewrite"`. `BranchList.tsx`는 `useMergeHint`의 `kind === "into"`일 때 "지금" 줄 아래에 `<Button>` "main에 합치기"(`merge-into`)를 둔다. `useSyncStore.paused`는 인증 실패로 자동 원격 확인을 멈춘다(D-055). 역 메뉴 대화상자의 틀(`features/history/menu/dialogs/Frame.tsx`)과 복사 함수(`features/history/menu/copy.ts`)가 있다. 폴더 고르기는 `lib/dialog.ts`, 프로젝트 열기는 `useOpenProject` 한 곳.
- 용어 `pr`(검토 요청, safe)·`clone`(복제, safe)은 이미 spec.md 표와 glossary에 있다. `query.rs`의 `remote_host`가 홈 노선도의 upstream 이름표 "GitHub"를 가린다(원격 주소 해석이 한 곳 더 생긴다).
- `redact`는 `gho_`·`ghp_`·`github_pat_` 등 토큰 접두사와 주소 속 자격 증명을 가린다. CSP는 `connect-src ipc: http://ipc.localhost`라 웹뷰는 GitHub에 직접 닿지 못하고 `img-src 'self' data:`라 원격 이미지(아바타)도 못 불러온다.
- `Cargo.lock`에는 TLS 없는 `reqwest 0.13`(Tauri 내부), `zbus 5.19`(`tauri-plugin-opener`), `windows-sys 0.61`이 이미 있다. TLS 구현(rustls·openssl·native-tls)·keyring은 없다. CI `ubuntu-22.04 기본 git` 작업(컨테이너)은 `git build-essential curl ca-certificates pkg-config`만 설치하고 `cargo test --workspace --exclude app`을 돌린다(core·hosting·platform이 여기서 빌드된다). `deny.toml`은 MIT·Apache·BSD·ISC·Zlib·Unicode·MPL-2.0 등만 허용하고 `multiple-versions = "warn"`이다.
- `docs/progress.md` "사람만 줄 수 있는 것"은 "(아직 없음)"이다. 이 반복이 처음으로 사람이 줄 것(OAuth App client id)을 만든다.

## 완료 기준 (반복 전체)
두 OS(Ubuntu 22.04 git 2.34.1, Windows 11)에서 손으로, 가능한 것은 자동 테스트로 확인한다. 실제 GitHub 계정 확인은 `docs/progress.md` "사람이 할 일"이다.
- client id 없이 `pnpm check:full`·`cargo test --workspace`·CI 두 OS(`git-min` 포함)가 통과하고, 그때 설정의 "GitHub 연결"은 꺼진 채 "준비 안 됨"과 까닭이 보인다. `HIGIT_GITHUB_CLIENT_ID`를 넣어 빌드하면(디버그는 실행 환경 변수도) 켜진다.
- 연결(가짜 GitHub로 자동 시험, 실제 계정은 손 확인): 설정 → "GitHub 연결" → 코드와 브라우저가 열리고 → 앱이 `@로그인` 연결됨. 토큰은 OS 키체인에만 있고(자동 시험: 가짜 토큰 문자열이 앱 데이터·로그·오류·화면 타입·명령줄·환경 변수에 없음), "연결 끊기"가 키체인 항목·`github.json`·메모리를 지운다. 키체인을 못 쓰면 "이번 실행에만 저장됨"이고 껐다 켜면 미연결이다. 401은 저절로 연결을 끊고 "다시 연결"을 보인다.
- 연결된 상태에서 GitHub https 원격의 동기화·원격 확인·올리기가 helper로 인증되고(가짜 백엔드가 `AuthMode::Helper`를 받음, 실제 helper는 `git credential fill`로 확인), ssh 원격·다른 호스트·미연결은 지금과 같이 동작한다.
- 상단 "검토 요청"(GitHub 원격 프로젝트): 열림·닫힘·전체 목록, 줄 모양(번호·제목·상태 글자·브랜치·작성자·날짜), 고른 줄의 시험 결과·겹침·뒤처짐, "GitHub에서 열기", 더 보기. 연결 안 됨·준비 안 됨·오류(401·권한·레이트·네트워크)가 각각 안내된다. 제목에 HTML이 있어도 글자로 보인다.
- "새 검토 요청": 제목·설명·합칠 브랜치·초안을 정해 만들면 필요할 때 먼저 올린 뒤 만들어지고, 토스트 "검토 요청을 만들었어요 · 열기"가 뜬다. 이미 있으면 안내, 앞선 버전이 없으면 막힌다.
- 브랜치 목록: GitHub 프로젝트에서 "main에 합치기" 자리에 "검토 요청"(또는 "검토 요청 #N · 열림")이 먼저, "main에 합치기"는 글자 버튼으로 남는다. GitHub가 아니면 지금과 같다.
- 복제: 시작 화면 "복제 Ctrl+Shift+O"(작업 공간에서도 같은 키)로 주소를 붙여 폴더를 정하면 받아 오고 프로젝트가 열린다. 규칙 밖 주소·비어 있지 않은 폴더가 거절된다. 진행 "복제 중 · N초"와 3초 뒤 "취소"가 되고 취소·실패하면 이번에 만든 폴더만 지워진다. Git이 오래됐으면 "그래도 복제"를 체크해야 한다.
- 새 액션 2개(`clone`·`pr-create`)의 위험도가 용어표와 같고(`registry-glossary`) `Irreversible`이 없다. 새 용어 `pr-draft`·`checks`가 표·glossary 둘에 있다. 새 오류 코드마다 ko·en 문구가 있다(완전성 테스트).

- 800px 너비와 다크 모드에서 설정·복제·검토 요청·새 검토 요청이 겹치거나 잘리지 않는다(긴 제목·주소는 말줄임).
- 보안 점검: `rg "Authorization|Bearer" src-tauri/crates`가 `hosting`의 전송·요청 타입에만, `rg "credential.helper" src-tauri/crates`가 `git`의 `network.rs`·`clone.rs`에만, `rg "ureq"`가 `hosting`에만, 화면 `rg "invoke|fetch\("`가 `src/lib` 밖에 없음, 새 명령 11개가 네 곳에 있음, 색 값은 `tokens.css` 밖에 없음.
- `pnpm check:full`, 두 OS CI 초록, `cargo deny check` 통과. code-analyst 점검 위반 0건.

## 단계
각 단계 = 커밋 하나, 메시지는 `<영역>: <요약>`. Rust를 고친 단계는 커밋 전에 `pnpm check:full`. `core::view`·Tauri 명령·액션 목록이 바뀌면 같은 커밋에서 `cargo run -p app --bin gen-bindings`. 새 Tauri 명령은 `src/commands.rs`·`src/bindings.rs`·`build.rs`의 `COMMANDS`·`capabilities/default.json` 네 곳과 `src/lib/api.ts`를 같은 커밋에 넣는다(`tests/security_config.rs`가 확인). 새 액션은 architecture.md "새 액션 추가 절차"대로: spec 용어표·glossary(G1) → `GitOp`(git 단계) → `ActionInput`·`actions/<id>.rs`·`register_all`·`Outcome`/`ActionResult` → 화면 → 테스트(임시 저장소에서 실행 → 결과 → 되돌리기 없음 확인). `GitBackend`에 메서드를 더하면 가짜 구현 둘(`NoGit`, `FakeGit`)도 같은 커밋에서 고친다. 새 git 명령은 `args::Cmd` 변형(`--end-of-options`가 2.34.1에서 되는지)을 정하고 `git-min`에서 확인한다. 테스트 저장소는 `core.autocrlf false`·`user.name`·`user.email`·`commit.gpgsign false`를 저장소에 넣고 파일 이름에 Windows 금지 글자(`*?:<>|"`)를 쓰지 않는다. 테스트는 사용자 전역 설정과 실제 키체인·네트워크를 건드리지 않는다(`GIT_CONFIG_GLOBAL`·`GIT_CONFIG_NOSYSTEM`, 키체인은 모의 저장소, GitHub는 가짜 `HttpTransport`). 용어 호버는 `<Term>`, 문장 속 용어는 `t(id)`(D-029). 화면 문구는 `src/messages` ko·en(괄호·옛 용어·합쇼체 없음, `copy-rules`·`terms-in-messages` 테스트)에 두고 이름과 숫자만(D-049, 토스트·오류·연결 안내 문장은 D-057). 색은 `tokens.css` 변수만. 새 ErrorCode는 `messages`의 `errors`에 ko·en 문구를 같은 커밋에(완전성 테스트). 모든 새 화면 입력은 한글 조합 중(`isComposing`, WebKitGTK `keyCode 229`) Enter를 무시한다. **토큰·device code는 어떤 단계에서도 화면 타입·로그·오류·명령줄·주소에 넣지 않는다.**

GitHub 판정 `GitHub::detect(url)`은 호스트가 정확히 `github.com`일 때만. core의 `query.rs::remote_host`는 G10에서 이 함수로 바꾼다. ② `HttpRequest { method, url, bearer: Option<SecretString>, headers, body }`·`HttpResponse { status, headers, body }`·`trait HttpTransport: Send + Sync { fn send(&self, req: &HttpRequest) -> Result<HttpResponse, TransportError> }`·`TransportError::{Timeout, Connect, TooLarge, Other}`. `Debug`는 `bearer`를 `<가림>`으로. ③ `GitHubConfig { client_id: Option<String>, api_base, web_base, scope }`(`api_base`·`web_base`는 기본 `https://api.github.com`·`https://github.com`이고 테스트가 바꾼다), `client_id`는 영숫자 8~64자만 받고 아니면 `None`(준비 안 됨). ④ `HostingError::{NotConfigured, Unauthorized, Forbidden { rate_limited, sso }, NotFound, Moved, Validation(ValidationKind), Unreachable, Unavailable, BadResponse, Cancelled}`. `Display`·`Debug`에 토큰·서버 응답 본문이 없고, 본문은 앞 200자만 `detail()`로 호출한 쪽에 준다(core가 `redact`).

G5. hosting: GitHub 로그인(device flow)과 사용자 확인 (`hosting: add github device flow and current user`)
- 목표: 코드 받기 → 폴링 → 토큰 받기 → 누구인지 확인을 가짜 전송으로 시험하며 만든다.
- 바꿀 파일: `crates/hosting/src/{github.rs, login.rs}`(+테스트), `lib.rs`(`trait HostingProvider`와 `GitHub` 구현).
- 내용: `trait HostingProvider: Send + Sync { id, detect, begin_login, poll_login, current_user, list_prs, pr_detail, create_pr }`(뒤 셋은 G6)와 `GitHub::new(transport: Arc<dyn HttpTransport>, config)`. `begin_login()` = `POST {web_base}/login/device/code`(폼: `client_id`, `scope=repo`, `Accept: application/json`). 응답 검증: `verification_uri`가 설정의 `{web_base}/login/device`와 정확히 같아야 하고(아니면 `BadResponse`), `user_code`는 `^[A-Z0-9]{4}-[A-Z0-9]{4}$`, `expires_in` 60~1800초·`interval` 1~60초로 보정, `device_code`는 `SecretString`. `poll_login(challenge)` = `POST {web_base}/login/oauth/access_token`(폼: `client_id`, `device_code`, `grant_type=urn:ietf:params:oauth:grant-type:device_code`): `authorization_pending` → `Pending`, `slow_down` → `SlowDown { interval }`(응답 값, 없으면 +5), `expired_token` → `Expired`, `access_denied` → `Denied`, `device_flow_disabled`·`incorrect_client_credentials` → `NotConfigured`, 성공이면 `token_type`이 bearer일 때만 `Granted(SecretString)`(`refresh_token`은 버림). `current_user(token)` = `GET {api_base}/user` → `HostUser { login, id, name }`. 모든 요청에 `User-Agent: higit/<버전>`·`Accept`·`X-GitHub-Api-Version: 2022-11-28`, 폼 본문은 `percent-encoding`.
- 테스트(가짜 전송이 요청을 기록): 정상 흐름(코드 → pending 둘 → slow_down → 토큰 → 사용자), 만료·거절·`device_flow_disabled`, 다른 호스트의 `verification_uri`·모양이 틀린 `user_code`·HTML(프록시 로그인 페이지)·빈 응답·JSON 아님은 `BadResponse`, 요청 URL·본문·헤더(`Authorization` 제외)에 토큰·`device_code`가 없음, `current_user`의 401은 `Unauthorized`.

- Windows/Ubuntu: 차이 없음.
- 보안: 서버가 준 URL을 열거나 따라가지 않는다(상수 주소만). `device_code`는 `SecretString`.

G6. hosting: 검토 요청 API (`hosting: add pull request list, detail and create`)
- 목표: 목록·상세·만들기를 가짜 전송으로 시험하며 만들고, 오류를 한 표로 매핑한다(C4·C5).
- 바꿀 파일: `crates/hosting/src/{pr.rs, api.rs}`(+테스트), `lib.rs`.
- 내용: `list_prs(token, repo, PrQuery { state: Open|Closed|All, head_branch: Option<String>, page, per_page ≤ 50 })` = `GET /repos/{o}/{r}/pulls?state=&per_page=&page=&sort=updated&direction=desc[&head={o}:{branch}]` → `PrPage { items, has_more }`(`Link: rel="next"`). `PullRequest { number, title, state: Open|Closed|Merged, draft, head_branch, head_owner: Option<String>(포크면), base_branch, author: Option<String>, created_at, updated_at }`(시각은 `YYYY-MM-DDTHH:MM:SSZ` 고정 형식이라 직접 파싱해 unix 초로, 새 의존성 없음). `pr_detail(token, repo, number)` = `GET pulls/{n}`의 `mergeable_state`(`clean`·`dirty`·`behind`·`blocked`·`unknown` 등)를 `Mergeable::{Clean, Conflicts, Behind, Blocked, Unknown}`으로, head sha로 `GET commits/{sha}/check-runs?per_page=100`을 `ChecksSummary { success, failed, pending }`으로(`success`·`neutral`·`skipped` = 성공, `failure`·`timed_out`·`cancelled`·`action_required` = 실패, `conclusion` 없음 = 진행). check-runs가 403·404면 `checks: None`이고 상세 전체를 실패시키지 않는다. `create_pr(token, repo, NewPr { title, body, head, base, draft })` = `POST /pulls`(본문은 `serde_json`으로만 만든다) → 201. 오류 표: 401 → `Unauthorized`, 403 → `Forbidden { rate_limited: X-RateLimit-Remaining == 0, sso: X-GitHub-SSO 있음 }`, 404 → `NotFound`, 422 → `Validation`(`errors[].message`에 "A pull request already exists" → `AlreadyExists`, "No commits between" → `NoDifference`, 그 밖 → `Invalid`), 5xx → `Unavailable`, 연결·시간 초과 → `Unreachable`, 301·307·308은 `Location`이 **같은 호스트 https**(`api.github.com`)일 때만 같은 요청을 최대 3번 다시 보내고 아니면 `Moved`. 입력 검사: 제목 비어 있지 않음·256바이트 이하·제어 문자(탭·개행 제외) 없음, 본문 64KB 이하, 브랜치 이름 255바이트 이하·공백 없음.
- 테스트(가짜 전송): 목록 JSON 표본(열림·닫힘·합쳐짐(`merged_at`)·초안·포크 head·삭제된 head 저장소(`null`)·탈퇴 작성자(`null`)·한글·이모지·1000자 제목), `Link` 헤더 파서, 상세 매핑 표와 check-runs 집계 표, 생성 본문 JSON(따옴표·개행·유니코드·`\`가 정확히 이스케이프됨), 오류 표(401·403 셋·404·422 셋·500·타임아웃), 리디렉트: 같은 호스트는 따라가고 다른 호스트·http는 **두 번째 요청이 기록되지 않고 `Moved`**, 요청 URL에 사용자 글자가 이어 붙지 않음(저장소 조각은 검증된 값을 percent-encode).
- 완료 기준: `cargo test -p hosting`.
- Windows/Ubuntu: 차이 없음.
- 보안: 사용자 글자는 serde로만 직렬화하고 문자열을 이어 붙여 JSON·URL을 만들지 않는다. 리디렉트 때 토큰이 다른 호스트로 가지 않는다.

- 목표: 실제 전송 구현에 시간·크기·리디렉트·프록시 규칙을 넣고 로컬 가짜 서버로 시험한다.
- 바꿀 파일: `crates/hosting/src/ureq_transport.rs`(+테스트), `lib.rs`.
- 내용: `UreqTransport::new()`: https만(`https_only`), 리디렉트 0(위 G6가 직접 처리), 연결 5초·전체 15초, 응답 본문 2MB 상한(넘으면 `TooLarge`), 프록시는 환경 변수(`HTTPS_PROXY` 등)를 따른다, `Authorization: Bearer`는 `HttpRequest.bearer`에서만 만든다, 오류 변환에 URL·헤더를 넣지 않는다. `#[doc(hidden)] allow_http_for_tests()`로 평문 로컬 서버를 허용한다(`CliBackend::allow_local_remotes_for_tests`와 같은 방식).
- 테스트(로컬 `TcpListener` 스레드): 200 JSON, 401 본문, 느린 응답이 시간 제한(테스트에서는 짧은 제한 주입)으로 `Timeout`, 큰 본문이 `TooLarge`, `Location` 응답은 전송이 따르지 않고 상태·헤더 그대로 돌려줌, 서버가 받은 요청 줄·헤더에 `Authorization`이 정확히 한 번이고 토큰이 URL·다른 헤더에 없음, `https://127.0.0.1:1`은 `Connect`(TLS 설정만 시험, 인터넷 의존 시험 없음).
- 완료 기준: `cargo test -p hosting` 두 OS와 `git-min`.
- Windows/Ubuntu: 회사 프록시·TLS 가로채기는 환경 변수 프록시와 OS 인증서 저장소가 맡는다(Windows 시스템 프록시 설정은 읽지 않음 — 위험 절).
- 보안: https만, 리디렉트는 앱이 직접, 크기·시간 상한.

### D. git

G8. git: 원격 주소 조회·인증 방식·취소 표시 분리 (`git: add remote urls, auth mode and split cancel flags`)
- 목표: core가 "git이 실제로 쓸 주소"를 보고 인증 방식을 정할 수 있게 하고, 원격 호출 하나에만 helper를 붙이며, 취소 표시를 둘로 나눈다(C3·C9).
- 바꿀 파일: `crates/git/src/backend.rs`(`remote_urls`, `set_helper_program`), `types.rs`(`RemoteUrls { fetch, push }`, `enum AuthMode { UserDefault, Helper }`, `GitOp::Fetch`·`Push`에 `auth: AuthMode`), `cli/mod.rs`·`cli/network.rs`·`cli/args.rs`(`Cmd::RemoteGetUrl`), `failure.rs`(+표 테스트), 가짜 구현 둘(`NoGit`, `FakeGit`: `remote_urls`·`set_helper_program`), `crates/core/src/actions/remote.rs`와 테스트의 `GitOp::Fetch`·`Push` 생성부(`auth: AuthMode::UserDefault`), `docs/architecture.md`(GitBackend 목록, GitOp, 취소 표시).
- 내용: ① `remote_urls(repo, remote)`: `remote get-url -- <원격>`과 `remote get-url --push -- <원격>`(insteadOf·pushInsteadOf·pushurl을 적용한 최종 값. `--end-of-options`가 2.34.1에서 되는지 시험하고 안 되면 이름을 core가 이미 `validate_ref_like`로 거른다). ② `set_helper_program(Option<PathBuf>)`는 앱 실행 파일 경로를 백엔드에 한 번 알린다(없으면 `Helper`를 줘도 `UserDefault`로 동작). `run_network`는 `AuthMode::Helper`이고 경로가 있을 때만 이 호출에 `-c credential.helper=`와 `-c credential.helper=!"$HIGIT_CREDENTIAL_HELPER" --git-credential`(상수 문자열), 환경 변수 `HIGIT_CREDENTIAL_HELPER=<경로>`를 더한다. 그 밖의 인자·환경은 지금과 같다(`UserDefault`는 인자 모양이 지금과 같음을 스냅샷으로). ③ 취소 표시를 (저장소 경로, 종류: 사람이 시킨 작업 / 저절로 하는 확인)으로 나눈다: `request_cancel`·`clear_cancel`·`tracked`는 사람이 시킨 쪽, `NetMode::Background`는 자기 쪽만 본다. ④ `failure.rs`에 새 종류 `HttpForbidden`("The requested URL returned error: 403"), `RemoteNotFound`("Repository not found", "The requested URL returned error: 404"), `GithubWorkflowScope`("refusing to allow an OAuth App to create or update workflow", "without `workflow` scope")를 `RemoteUnreachable`·`PushRejected` **앞에** 둔다(기존 표 테스트는 그대로 통과해야 한다).
- 테스트(실제 git): `remote_urls`(`insteadOf`·`pushInsteadOf`·`pushurl`이 든 임시 저장소에서 fetch/push 값이 다름), `Helper` 호출이 `credential fill`(입력 `protocol=https\nhost=github.com\n`)에서 **스텁 helper 스크립트**를 부르고 출력이 그대로 나옴(스텁은 `HIGIT_CREDENTIAL_HELPER`가 가리키는 파일), 사용자 `credential.helper` 설정에 둔 표식 스크립트는 이 호출에서 **불리지 않음**·`UserDefault`에서는 지금처럼 불림, 경로에 공백·한글·작은따옴표(`a b/한글'x`)가 든 helper도 호출됨(Windows CI에서 Git for Windows `sh`로), 취소: 사람이 취소해도 백그라운드 확인은 계속되고 백그라운드 표시가 사람이 시킨 작업을 끝내지 않음, `failure.rs` 새 문구 표(403·404·워크플로 범위)와 기존 문구가 그대로. `git-min`에서 `remote get-url [--push]`, `-c credential.helper=`.
- 완료 기준: `cargo test -p git` 두 OS와 `git-min`, `cargo test --workspace`.
- Windows/Ubuntu: Git for Windows의 `sh`가 `"$HIGIT_CREDENTIAL_HELPER"`를 풀 때 MSYS가 환경 변수 값을 경로로 바꿀 수 있다(따옴표 안 변수로 쓴다, D-100의 `HIGIT_GIT`과 같은 방식). 경로의 공백·한글.
- 보안: 환경 변수에는 경로만 들어가고 토큰은 없다. 명령 문자열은 상수다. `AuthMode`는 core가 정하고 화면 값이 아니다.

G9. git: 복제 (`git: add clone with progress and cancel`)
- 목표: `git clone`을 원격 작업과 같은 감시(시간 제한·진행·취소)로 돌린다.
- 바꿀 파일: `types.rs`(`GitOp::Clone { url, name, auth }`), 신규 `cli/clone.rs`(+`clone_tests.rs`), `cli/args.rs`(`Cmd::Clone`), `cli/mod.rs`(`run`), 가짜 구현 변화 없음(`run`만 쓰임), `docs/architecture.md`(GitOp, 시간 제한 표 "복제").
- 내용: `GitOp::Clone`에서 `repo`는 **부모 폴더**(`Init`처럼 대상 폴더 인자)이고 대상은 `repo/name`이다. 명령은 `git clone --progress --no-recurse-submodules --origin origin <url> <name>`(주소 앞 `--`/`--end-of-options`는 G9에서 2.34.1로 시험해 정한다). 실행은 `run_network`와 같은 감시(10분·멈춤 90초·`Foreground`)이고 cwd는 부모 폴더, 진행 알림·취소 표시의 키는 **대상 경로**다(G8의 분리된 표시 중 사람이 시킨 쪽). `auth`는 C3대로. 실패 뒤 폴더 정리는 core가 한다(git은 SIGTERM에서만 스스로 지운다).
- 테스트(실제 git, `allow_local_remotes_for_tests`): 로컬 bare 원격 복제 성공(원격 이름 origin·기본 브랜치·태그), 한글·공백 폴더 이름, 대상이 이미 있으면 git이 거절, 허용 안 된 `file://`·`ext::sh -c x`는 `ProtocolNotAllowed`, `--upload-pack=x`처럼 `-`로 시작하는 주소가 옵션으로 읽히지 않음, 서브모듈이 든 저장소를 복제해도 서브모듈 폴더는 비어 있음, 취소 표시를 미리 켜면 `Cancelled`로 끝남(깃발 시험), `git-min`.
- 완료 기준: `cargo test -p git` 두 OS와 `git-min`.
- Windows/Ubuntu: 대상 경로 길이(Windows 260자는 core가 200자로 거절), 대소문자 무시 파일시스템, 파일 이름 금지 글자가 든 저장소는 Windows 체크아웃에서 git 오류(그대로 알림).
- 보안: 주소는 core가 검사한 뒤에만 온다. 서브모듈을 받지 않는다. 전송 방식은 `GIT_ALLOW_PROTOCOL`.

G11. core: credential helper와 인증된 원격 작업 (`core: github credential helper and authenticated remote actions`)
- 목표: `--git-credential`로 다시 실행된 앱이 helper로 답하고, 원격 작업이 조건이 맞을 때만 그 helper로 인증한다(C3).

- 내용: helper 입력은 stdin의 `key=value` 줄(8KB·64줄 상한, 빈 줄에서 끝)이고 첫 인자 `get`만 처리한다. 답: `protocol=https`와 `host=github.com`(소문자 비교, 포트·접두사 없음)이 **정확히** 맞고 키체인에 토큰이 있을 때만 `username=x-access-token\npassword=<토큰>\n\n`을 stdout에 쓰고, 그 밖에는 아무것도 쓰지 않고 0으로 끝낸다. `store`·`erase`·모르는 인자는 아무것도 안 하고 0. 토큰은 `Keychain.get`으로만 읽고(세션 토큰은 다른 프로세스라 못 씀) 실패하면 빈 답. 로그·오류·패닉 메시지에 토큰이 없고 stdout 쓰기 실패는 무시한다. `auth_for`: GitHub 연결됨 && `remembered`(키체인에 저장됨) && `remote_urls`의 fetch·push 주소가 **둘 다** `https`·호스트 정확히 `github.com`·사용자정보 없음 → `Helper`, 아니면 `UserDefault`(자동 원격 확인 포함). `Helper`를 쓴 호출이 `HttpAuthFailed`·`HttpForbidden`으로 실패하면 `current_user`로 토큰을 한 번 확인해 401이면 `on_unauthorized()` 후 "연결이 끊겼어요" 오류로 바꾼다(네트워크가 막혔으면 원래 오류 그대로). 연결 성공 때 화면이 `useSyncStore.paused`를 풀게 하는 것은 G15.

## 위험과 열린 질문
- **TLS(`ring`)와 키체인 스토어의 두 OS 빌드**: G2가 가장 먼저 확인한다. Windows에서 `ring`이 NASM·`crt-static`·"VC++ 런타임 없이 뜸" 확인에서 막히면 `native-tls`(schannel)로, zbus 스토어가 Linux에서 안 되면 dbus 스토어로 바꾸고(`ubuntu-22.04 기본 git` 작업에도 패키지 추가) D-110에 반영한다. 그래서 G2 뒤의 단계는 선택에 의존하지 않게 `HttpTransport`·`Keychain` 틀 뒤에 감췄다.
- **Linux 키체인이 없는 환경**(서버·WSL·최소 설치·Secret Service 잠금 거절): 평문으로 내려가지 않는다. 그 실행만 메모리 토큰이라 검토 요청은 되지만 git 인증은 사용자 기본으로 남고(다른 프로세스인 helper는 세션 토큰을 못 읽음), 화면은 "이번 실행에만 저장됨". 사용자가 터미널에서 Secret Service를 갖추기 전에는 Ubuntu 서버형 환경에서 매번 연결해야 한다(D-040이 정한 비용).
- **helper를 앱 실행 파일로 다시 실행하는 방식**(C3): Windows 릴리스 exe는 GUI 하위 시스템(`windows_subsystem = "windows"`)이라 git이 준 파이프 표준 입출력이 되는지 손으로 확인해야 한다. 안 되면 대안은 별도 console 실행 파일(`bin` 하나 더, 반복 5의 .msi·.deb·AppImage 묶음과 같이)이다. 반복 5의 single-instance 플러그인은 `main()`의 `--git-credential` 분기보다 뒤에 등록해야 helper가 기존 창으로 넘겨지지 않는다(반복 5 계획에 적을 것). Git for Windows `sh`가 공백 있는 설치 경로를 환경 변수로 푸는 동작은 G8 시험이 두 OS에서 확인한다.
- **D-040 문장 해석**(C3): 연결된 GitHub https 호출에서는 사용자 helper(GCM)가 불리지 않는다. 설정은 그대로이고 연결을 끊으면 돌아오지만, GCM에 다른 GitHub 계정을 쓰던 사용자는 hiGit이 연결한 계정으로 올리게 된다. 4b의 "git에도 hiGit 로그인을 쓰기" 설정이 이를 푼다.
- **scope `repo` 하나**: 워크플로 파일(`.github/workflows/*`)을 만들거나 고치는 올리기는 GitHub가 `workflow` 범위가 없는 OAuth 토큰을 거절한다. `failure.rs`가 이를 `GithubWorkflowScope`로 알려 "터미널이나 다른 도구로 올려 주세요"를 안내한다. `workflow` 범위까지 요청할지는 사람이 정한다(질문 ②).
- **조직의 OAuth 앱 제한·SSO**: 조직이 제3자 앱을 막거나 SAML SSO 승인이 필요하면 404·403이 나온다. `X-GitHub-SSO` 헤더를 `Forbidden { sso }`로 알리고 앱 권한 페이지 링크(`HostingPage::AppSettings`)를 준다.
- **GitHub 서버 가정**: device flow는 OAuth App 설정의 "Enable Device Flow"가 켜져 있어야 한다(꺼져 있으면 `device_flow_disabled` → 준비 안 됨 안내). 레이트 한도(인증 시간당 5000)는 C12로 아낀다. API 모양(`mergeable_state`·`check-runs`)은 가짜 응답 표본으로 시험하므로 실제 응답과 어긋나면 사람이 확인하는 손 확인에서 드러난다.
- **회사 프록시·TLS 가로채기**: `ureq`는 환경 변수 프록시를 읽지만 Windows 시스템 프록시 설정은 읽지 않는다. OS 인증서 저장소를 쓰면 회사 루트 인증서는 따른다. 안 되는 환경은 후속 설정으로.
- **복제**: 대상 폴더를 지우는 코드는 위험하므로 "이번 실행이 만든·링크가 아님·부모가 같음"을 시험으로 고정했다. Windows에서 git이 강제 종료된 뒤 파일이 잡혀 지우기가 실패할 수 있다(남기고 알림). 보안 수정이 없는 오래된 git으로 복제하는 경우 한 번 더 확인을 받지만 배포판 패키지 git은 판정에서 빠진다(D-050).
- **`pr-create`의 부분 실패**: 올리기는 됐는데 생성이 실패하면 원격에 브랜치만 남는다. 다시 누르면 올리기를 건너뛰고 만들기만 한다(되돌리지 않는다).
- **그림이 없는 화면**: 설정·복제·검토 요청·새 검토 요청은 그림이 없다. 처음 쓴 모양이 어색하면 `docs/design.md`만 고치고 데이터 모델은 그대로 둔다.
- 구현 중 알게 된 것은 이 문서가 아니라 `docs/progress.md`에 적고, 결정이 필요하면 `docs/decision.md`에 "(자동 결정)"으로 올린 뒤 이어 간다.
- code-analyst 검토 때 먼저 볼 곳: G11(helper가 github.com 외에 답하지 않는지, 토큰이 stdout 파이프 말고 어디에도 안 나가는지, 사용자 helper를 비우는 조건이 `auth_for` 한 곳인지), G6(리디렉트에서 토큰이 다른 호스트로 안 가는지, JSON·URL을 문자열로 안 만드는지), G12(지우기 범위·URL 규칙·Windows 예약 이름), G10(토큰이 화면 타입·오류·로그에 없는지, `app_open_hosting_page`가 주소를 안 받는지), G8(`UserDefault`가 지금 인자와 같은지·취소 표시 분리가 `tracked` 흐름을 안 깨는지).
- 질문(사람 확인이 필요하면): ① GitHub OAuth App을 어느 계정(개인·조직)에 어떤 이름·홈페이지로 만들지(D-009의 `hiGit` 이름 확인과 같이), "Enable Device Flow" 체크, client id를 개발은 환경 변수로 릴리스는 저장소 변수(`vars`, 비밀 아님)로 넣는 것. ② scope를 `repo`만 쓸지 `repo workflow`까지 쓸지(추천 `repo`). ③ C3: 연결된 GitHub https 호출에서 사용자 helper(GCM)를 쓰지 않는 것에 동의하는지. ④ 이름·이메일·처음 실행 화면·덮어쓰며 올리기 등을 반복 4b로 미루는 것(C8). ⑤ 새 의존성(`ureq`+`rustls`, `secrecy`, `keyring-core`+스토어 둘)과 G2 결과에 따른 대안 사용. 사람 확인 없이 진행하는 지시이므로 위 추천안으로 구현하고 `docs/decision.md`에 "(자동 결정)"으로 남긴다.

### 사람이 할 일 (`docs/progress.md`에 G20에서 옮김)
- **사람만 줄 수 있는 것**: GitHub OAuth App의 client id. 만드는 방법: GitHub → Settings → Developer settings → OAuth Apps → New OAuth App, 이름 `hiGit`, Homepage URL은 프로젝트 주소(아무 https), Authorization callback URL은 필수 칸이라 `http://127.0.0.1`(device flow는 쓰지 않음), 만든 뒤 **"Enable Device Flow" 체크**, Client ID를 복사한다(비밀 아님, **client secret은 만들지도 넣지도 않는다**). 개발: `HIGIT_GITHUB_CLIENT_ID=<id> pnpm tauri dev`, 릴리스 빌드: CI 저장소 변수.
- **실제 계정으로 확인(두 OS)**: 연결 → 비공개 GitHub 저장소 HTTPS에서 동기화·원격 확인이 로그인 창 없이 되는지(Windows는 GCM 창이 안 뜸), 자동 원격 확인이 조용한지, 연결 끊기 뒤 지금처럼 돌아오는지, 검토 요청 목록·상세(시험 결과·겹침)·만들기·"열기", 복제(공개·비공개, 취소, 한글 폴더), 브랜치 목록의 "검토 요청".
- **OS 키체인**: Windows 자격 증명 관리자에 `dev.higit.desktop` 항목이 생기고 끊으면 사라지는지, Ubuntu 키링 잠금 해제 창, `cargo test -p platform -- --ignored`로 실제 키체인 왕복. 키체인이 없는 환경에서 "이번 실행에만 저장됨".
- **helper**: Windows 릴리스 exe가 git의 파이프 입출력을 받는지(`pnpm tauri build --no-bundle` 결과로), 설치 경로에 공백이 있을 때, `higit --git-credential get`에 `protocol=https`·`host=evil.example`을 넣으면 빈 답인지.
- **웹뷰**: Ctrl+Shift+O가 WebView2·WebKitGTK에서 앱에 오는지, 설정·복제·새 검토 요청 대화상자 한글 IME(조합 중 Enter), 코드 복사 두 웹뷰, 800px·다크.

### 바뀐 결정
- **C3·C10(D-111·D-118) 보탬: 받은 저장소의 `http.*` 설정이 있으면 hiGit helper를 붙이지 않는다.** helper가 `host=github.com`만 보고 토큰을 내도, 저장소 설정이 TLS 검증을 끄거나(`http.sslVerify=false`) 연결을 돌리면(`http.proxy`, `http.curloptResolve`, 저장소 안의 `http.sslCAInfo`·`sslCAPath`, `http.proxySSLVerify`, `http.pinnedPubkey`, `remote.<이름>.proxy`) 중간자가 토큰을 받는다. `auth_for`는 저장소 로컬·워크트리 범위(`git config --show-scope --get-regexp -z`의 local·worktree)에 이런 키가 하나라도 있으면 `UserDefault`다(사용자 전역 설정은 사용자가 정한 것이라 그대로). 원격 주소는 `get-url --all`과 `get-url --push --all`로 읽고 **모두** `https://github.com/...`일 때만 `Helper`. 신뢰 확인 목록(`trust.rs`)에 `http.*`를 넣는 것은 반복 5-0에서.
- **C5(D-113) 바꿈: `pr-create`는 올리기를 하지 않는다.** 화면이 먼저 `push`(upstream이 없으면 `push`가 upstream을 정함)를 `executeAction`으로 부르고 끝나면 `pr-create`를 부른다. `pr-create`는 올라가 있지 않으면 `NotPushed`로 거절한다. 올리기는 기존 위험도·journal·취소·원격 잠금을 그대로 쓰고 `pr-create`는 `Safe`/`Nothing`(용어 `pr` 위험도와 같다).
- **C5 보탬: PR의 `head`는 로컬 브랜치 이름이 아니라 올릴 원격 브랜치 이름**(`Upstream::push_target`이 주는 값)이다. upstream 브랜치가 `base`와 같거나 기본 브랜치면 거절한다(`PrSameBranch`, 새 오류 코드). `PrRowView.isCurrentBranch`와 `pr_list(branch)` 필터도 원격 브랜치 이름으로 맞춘다. 취소 표시는 `create_pr` 호출 직전에 한 번 더 본다.
- **C7(D-115) 좁힘: 복제 주소는 D-035 그대로** `https://…`, `ssh://…`, `git@host:path`만(아무 `user@host:path`는 받지 않는다). 대상은 **새로 만들거나 비어 있는 폴더**만이고 그 폴더(있으면)와 부모가 링크가 아니며, 부모가 어떤 저장소의 `.git` 폴더 안이면 거절한다. 복제만 열린 저장소 요구(D-037)의 예외인 까닭(새 폴더를 만드는 작업이라 열린 저장소가 있을 수 없음, 대신 대상 경로 검사)을 D-115에 적는다.
- **C9(D-117) 근거 보탬**: 취소 표시를 사람·자동으로 나누는 것은 D-108의 미룸을 이행한다. D-068 잠금 때문에 효과는 작다는 점도 적는다.

### 단계별 고침
- **G2**: `ring`도 `cargo deny`에서 `OpenSSL` 라이선스 확인이 필요할 수 있다(실제 `deny check` 결과로 `deny.toml`을 고치고 까닭을 적는다). `zbus-secret-service-keyring-store`의 런타임 기능은 트리에 이미 있는 `async-io` 쪽으로 통일. `THIRD_PARTY_NOTICES.md`에 rustls·ring·인증서 번들·키체인 스토어 라이선스를 더한다. `cargo tree -p hosting`으로 내부 크레이트 의존 없음 확인.
- **G6**: 상태 표에 429·`Retry-After`(보조 한도는 403이면서 `Retry-After`), 410·451·304, 2xx인데 JSON 아님(`BadResponse`). 서버가 준 `head.sha`는 40·64자 16진수만(아니면 `BadResponse`) 받아 URL 조각에 넣는다. `check-runs` `total_count > 100`이면 "일부만". 초안이 안 되는 저장소의 422를 `PrInvalid` 문구에 반영. 오류 `detail`에 서비스가 쥔 토큰·`device_code`의 정확한 문자열 치환을 더한다(redact는 접두사 있는 토큰만 가린다).
- **G7**: `ureq` 3은 상태를 오류로 바꾸지 않게 하고 리디렉트는 0(직접 처리). 리디렉트 `Location`은 절대 주소로 풀어 호스트가 정확히 `api.github.com`, https, 포트·사용자 정보 없음일 때만 따른다. 시험에 "404가 오류가 아니라 응답으로 옴".
- **G8을 셋으로**: G8a 실패 종류 3개(`HttpForbidden`·`RemoteNotFound`·`GithubWorkflowScope`) + `ErrorCode`·`From` 매핑·ko/en 문구·바인딩·`failure.rs` 표 시험(같은 커밋, 컴파일이 깨지지 않게). G8b 취소 표시 분리(C9). G8c `remote_urls`(`--all`) + 로컬·워크트리 `http.*` 조회 + `AuthMode` + helper 지정.
- **G10을 둘로**: G10a 서비스 + 오류 코드·문구, G10b 명령 + `api.ts`. 새 명령은 모두 `async` + `blocking()`(키체인 창·HTTP·git이 메인 스레드를 막지 않게). `connect_poll`은 HTTP 동안 서비스 잠금을 쥐지 않고 "진행 중" 표식으로 두 번째 호출은 네트워크 없이 `Pending`. 만료는 시작 시각 + 서버 `expires_in`(60~1800초로 보정) 한 곳에서. 401 처리는 토큰 세대 번호가 같을 때만 지운다(늦은 401이 새 연결을 지우지 않게). `remembered`는 "이번 실행에 키체인에서 읽었거나 썼다"이고 백그라운드 원격 확인은 아직 읽은 적이 없으면 `UserDefault`(키체인 잠금 해제 창을 저절로 띄우지 않게).
- **G11**: helper 입력은 `[]`로 끝나는 배열 키(`wwwauth[]`·`capability[]`)를 받고 `protocol`·`host`가 두 번이면 거절, 모르는 키는 무시. 키체인은 `protocol=https`·`host=github.com` 일치를 본 뒤에만 읽는다. 입력에 `username`이 있으면 답하지 않는다. helper 전체 10초 제한. `main.rs`는 `std::env::args_os()`로 `init()`·로그·Tauri보다 먼저 분기하고 어떤 경우에도 stdout에 다른 것을 쓰지 않고 0으로 끝난다. helper 경로는 `Helper`를 줄 때마다 `current_exe_path()`를 다시 부르고 파일 존재를 확인. 인증 실패 뒤 토큰 확인(`current_user`)은 사람이 누른 작업에서만, 원격 잠금 밖에서. `useAutoFetch`의 `AUTH_FAILURES`에 `httpForbidden`·`remoteNotFound`를 더한다. 빌드된 `app --git-credential`을 실제로 돌리는 시험(다른 호스트·`store`·`erase`·모르는 인자 → 빈 출력·종료 0·키체인 접근 없음)을 `src-tauri/tests/`에.
- **G12를 둘로**: G12a 복제 액션(대상 경로 검사·잠금 키·`tracked`·`running`을 대상 경로로 일관되게, `cancel`이 열린 폴더를 먼저 요구하지 않게 하고 대상 경로와 정확히 같을 때만 복제를 취소), G12b `clone_defaults`·`bootstrap` 연결. 부모가 저장소 안이어도 `run_network`의 `core.sshCommand` 조회가 그 저장소 설정을 읽지 않게(복제는 전역만). 복제 전체 상한은 1시간, 멈춤 감지 90초는 그대로. `--no-recurse-submodules`와 https → http 리디렉트 거절을 시험으로 고정. 복제 뒤 화면이 `project_open`을 거치는지 시험.
- **G13을 둘로**: G13a 조회(`hosting_context`는 요청 한 번에 원격 조회 한 번 + 짧은 캐시, 기존 `remote_host`를 `parse_remote`로 바꿀 때 사용자 정보가 든 https 주소가 "GitHub" 이름표에서 빠지는 변화를 시험), G13b `pr-create`(위 C5 고침).
- **G15·G19**: device flow 대기 중 창 포커스가 돌아오면 바로 `poll` 한 번(core가 간격을 지킨다). 상단 바 컨트롤 수(≤5)를 "원격 없음 + 미연결"의 "GitHub 연결"까지 합쳐 시험.
- **G1**: D-040의 "keyring crate"를 "keyring-core"로(D-110 보완) 적는다. D-109에 scope `repo`가 넓다는 점을 한 줄.
- **G20**: code-analyst 점검 줄에 `http.*` 확인, "helper는 호스트 일치 뒤에만 키체인", 복제 대상 폴더 지우기 범위, `rg "credential.helper" src-tauri/crates`가 `network.rs`·`clone.rs`뿐인지를 더한다.

### 사람에게 묻지 않고 정한 것(planner가 질문으로 남긴 것)
- scope는 `repo` 하나. `.github/workflows/*`를 바꾸는 올리기가 거절되면 `GithubWorkflowScope` 안내(반복 4b에서 `workflow` scope 선택을 다시 본다).
- C3: D-040의 "사용자 helper를 그대로 둔다"는 "사용자 설정을 고치거나 지우지 않는다"로 읽는다. 연결된 GitHub https 호출 하나에서만 사용자 helper 대신 hiGit helper가 쓰인다.
- C8: 이름·이메일·처음 실행 화면·덮어쓰며 올리기·올린 기록 바꾸기·원격 브랜치 지우기/이름 바꾸기·태그 올리기·로컬 프로젝트를 GitHub에 올리기는 반복 4b로.
- 새 의존성(ureq 3 rustls, secrecy, keyring-core + 스토어)은 G2의 두 OS CI와 `cargo deny`가 통과할 때 쓴다. 막히면 계획의 대안 순서대로.
- 사람만 할 수 있는 것: GitHub OAuth App 등록("Enable Device Flow")과 client id(`HIGIT_GITHUB_CLIENT_ID`), 실제 계정으로 연결 확인. `docs/progress.md` "사람만 줄 수 있는 것"에 적는다.
