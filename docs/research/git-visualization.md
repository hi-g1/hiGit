# 브랜치·버전 기록 시각화 조사

- 날짜: 2026-10-15
- 상태: 조사 결과 (결정 아님). 채택하면 `docs/decision.md`에 결정으로 올리고 `docs/spec.md`, `docs/design.md`에 반영한다.
- 시안 그림: https://claude.ai/artifact/HVDjmLokT4ZE64H4q1y28d (같은 예시 기록을 8가지 방식으로 그린 페이지)

## 목적
비전공자도 설명 없이 브랜치와 버전 기록을 읽게 하려고, Git 도구가 아닌 여러 분야의 표현 방식을 조사했다.

## 예시 기록 (모든 시안 공통)
메인에서 "로그인 기능" 브랜치를 만들어 합쳤고, "오타 수정"도 합친 뒤 v1.0 태그를 달았다. "디자인 개편"은 아직 작업 중이다.

```
메인        시작 ─ 메인 화면 ─┬─ 설정 메뉴 ─ ◎로그인 합침 ─┬─┬─ ◎오타 합침 [v1.0]
로그인 기능                 └─ 로그인 화면 ─ 비밀번호 확인 ─┘ │ │
오타 수정                                                    │ └─ 오타 수정 ─┘
디자인 개편                                                  └─ 색상 변경 ─ 버튼 정리 (지금 여기)
```

## 8가지 표현

### ① 지하철 노선도 (교통 디자인, Harry Beck 1933)
- 대응: 브랜치 = 노선, 버전 = 역, 합치기 = 환승역, 현재 위치 = "지금 여기", 브랜치 끝 = 종착역.
- 규칙: 선은 가로와 45도만. 실제 간격 대신 순서만 표현.
- 좋은 점: 설명 없이 읽힌다. 교차가 적고 이름표 자리가 넉넉하다.
- 한계: 브랜치가 많아지면 노선 자동 배치 알고리즘이 필요하다(난이도 높음).
- 참고: https://www.ltmuseum.co.uk/collections/stories/design/transforming-tube-map-harry-becks-iconic-design

### ② 열차 운행 다이어그램 (철도 운영, E. J. Marey 1885)
- 대응: 가로축 = 실제 날짜, 세로 = 브랜치 줄, 선 기울기 = 걸린 시간. 쉬었던 기간은 회색 띠.
- 좋은 점: "이 브랜치 언제부터 멈췄나", "언제 몰아서 작업했나"가 보인다.
- 한계: 같은 날 저장이 몰리면 점이 겹친다. 기본 화면보다 "실제 시간으로 보기" 전환용.
- 참고: https://chance.amstat.org/?p=6922 , https://www.c82.net/blog/visualizing-metra

### ③ 영화 줄거리 차트 (영화·만화, xkcd 657)
- 대응: 선 = 사람. 같은 브랜치·합치기에 함께 있으면 선이 모인다.
- 좋은 점: 팀에서 누가 어디서 따로 일하고 언제 함께 합쳤는지 이야기처럼 읽힌다.
- 한계: 혼자 쓰는 프로젝트에선 선이 하나라 쓸모없다. "사람별로 보기" 보조 보기용.
- 참고: https://xkcd.com/657/

### ④ 음악·영상 편집기 트랙 (DAW, 영상 편집 타임라인)
- 대응: 브랜치 = 트랙, 버전 = 클립, 클립 길이 = 바뀐 양, 합치기 = 다른 색 점선 클립, 재생 헤드 = 시점 선택.
- 좋은 점: 재생 헤드를 끌어 "그 시점 상태"를 실행 전에 미리 본다.
- 한계: 갈라진 지점이 약하게 보인다. 전체 보기보다 "시점 미리보기" 기능으로 빌려 쓴다.

### ⑤ 갈라졌다 다시 만나는 강 (지리·통계 그래픽, Minard 흐름 지도, Sankey)
- 대응: 선 굵기 = 쌓인 변경 줄 수. 브랜치는 갈라졌다 합류하는 강줄기.
- 좋은 점: "이번 버전에서 가장 큰 작업"이 한눈에 보인다. 노선도 선 굵기로 얹을 수 있다.
- 한계: 파일 삭제·이동 때 줄 수가 튄다. 굵기에 상한을 두고 로그 눈금 사용.
- 참고: https://en.wikipedia.org/wiki/Charles_Joseph_Minard , https://en.wikipedia.org/wiki/Sankey_diagram

### ⑥ 게임 세이브 슬롯 (비디오 게임)
- 대응: 버전 = 세이브 카드, 브랜치 = 다른 루트, 되돌리기 = "이 시점 불러오기".
- 카드 내용: 버전 번호, 날짜, 메시지, 루트(브랜치) 색, 파일 수·줄 수, 버전 표시.
- 좋은 점: 되돌리기의 두려움을 줄인다. "불러와도 지금 버전은 남아요"가 자연스럽다.
- 한계: 구조는 안 보인다. 복구·되돌리기 화면 전용.

### ⑦ 이야기 분기 카드 지도 (인터랙티브 소설 Twine, 영화 스토리보드)
- 대응: 버전 = 카드. 끌어서 순서 바꾸기, 겹쳐서 묶기, 밖으로 빼서 버리기, 카드에서 메시지 고치기.
- 좋은 점: interactive rebase가 손으로 하는 카드 정리가 된다. 실행 전 결과가 배치로 보인다.
- 한계: 한 화면 20장 정도가 한계. 선택 구간 편집용.
- 참고: https://pinnguaq.com/learn/introduction-to-twine/

### ⑧ 지도 앱식 확대·축소 (지도 서비스의 축척별 정보)
- 단계: 멀리서 = 태그만 / 중간 = 합치기와 브랜치 곁가지 / 가까이 = 모든 버전.
- 좋은 점: 저장 수천 개 프로젝트에서도 길을 잃지 않는다.
- 한계: 단계 전환이 매끄러워야 하고, "지금 여기" 표시는 항상 보여야 한다.

## 검토했지만 뺀 것
| 표현 | 분야 | 이유 |
| --- | --- | --- |
| 가계도·계통수 | 족보, 생물 분류 | 갈라지기만 하고 합쳐지지 않아 합치기 표현이 어색하다 |
| 토너먼트 대진표 | 스포츠 | 합치기가 "한쪽 탈락"처럼 읽힌다 |

| 달력 잔디 | 운동·습관 앱 | 활동량만 보이고 구조가 없다. 홈 화면 작은 위젯 후보 |

## 추천 조합
1. 버전 기록 기본 화면: ① 노선도 + ⑧ 확대·축소 + ⑤ 선 굵기. 가로·45도 선, 합치기는 환승역 모양, "지금 여기"는 항상 표시.
2. 보기 전환: ② "실제 시간으로 보기", ③ "사람별로 보기". 같은 데이터에 배치만 바꾼다.
3. 시점 미리보기: ④ 재생 헤드. 기록 위에서 끌면 그 시점의 파일 상태를 옆에 보여준다.
4. 복구·되돌리기: ⑥ 세이브 카드. "불러와도 지금 버전은 남아요"를 항상 함께 표시.
5. 기록 정리하기: ⑦ 카드 지도.

## 구현 메모 (planner 참고)
- 노선도 배치: 브랜치별 줄(lane) 배정 + 45도 연결로 시작하고, 브랜치가 많을 때의 자동 배치는 별도 조사 과제로 둔다.
- 그리기는 SVG(수백 개까지) → 많아지면 Canvas로 전환할 수 있게 그리기 계층을 분리한다.
- 확대·축소 단계는 데이터 단계(버전만 / 합치기까지 / 전체)로 나누어 백엔드 log 조회에서 걸러 받는다.
- 색은 `docs/design.md`의 브랜치 그래프 6색과 토큰만 쓴다.
