# 자주 쓰는 동작을 바로 하기

- 날짜: 2026-10-15
- 상태: 조사 결과. 흐름 페이지 세 번째 안의 바탕. 채택하면 `docs/decision.md`에 올린다.
- 앞선 안: 노선도 지도 중심 두 번째 안. 지도가 너무 크고, 창을 띄워 채울 것이 많다는 의견을 받았다.

## 조사한 것
| 출처 | 내용 | 가져올 점 |
| --- | --- | --- |
| Aza Raskin, Never Use a Warning When You Mean Undo | 사람은 확인 창에 습관적으로 확인을 누른다. 확인보다 되돌리기가 실수를 더 잘 막는다. Gmail은 지운 메일을 바로 되돌릴 수 있게 한다 | 확인 창 대신 바로 하고 "되돌리기"를 띄운다 |
| Tower의 Undo | Cmd+Z 하나로 버전 저장, 스테이징, 브랜치 만들기, 바꾸기, 지우기, 합치기, 리베이스, 임시 보관을 되돌린다 | Git 앱에서도 거의 모든 동작을 되돌릴 수 있다. reflog와 백업 ref로 구현 |
| GitHub Desktop | 바뀐 파일을 처음부터 모두 체크. 브랜치를 바꿀 때 고친 파일을 그 브랜치에 남겨 둘 수 있다. 원격 상태를 주기적으로 확인 | 이번 버전에 넣기는 기본 전부, 갈아타기는 묻지 않고 맡겨 두기 |
| VS Code 소스 제어 | 메시지 칸의 반짝이 버튼으로 버전 이름을 만들어 준다. 마지막 버전 취소가 메뉴 하나. 동기화는 가져온 다음 올린다 | 이름 제안, 저장 취소, 동기화 버튼 하나 |
| GitButler | 여러 브랜치를 동시에 펼쳐 두고 변경을 끌어서 브랜치에 넣는다. 체크아웃이 없다 | 갈아타기의 부담을 없애는 방향. hiGit은 브랜치마다 고친 파일을 저절로 맡겨 두는 정도로 가볍게 |
| Slack, Linear의 검색 칸 | 찾는 이름이 없으면 그 자리에서 "새로 만들기" | 브랜치 메뉴의 찾기 칸에서 새 브랜치 |

## 원칙
1. 자주 쓰는 일은 한 번에 끝난다. 창을 띄우지 않고, 누르면 바로 하고, 아래에 "되돌리기"를 잠깐 띄운다. Ctrl+Z도 같다.
2. 채울 칸은 하나까지. 버전 이름 한 칸만 있고, 비워 두면 제안한 이름으로 저장한다.
3. 방향은 앱이 고른다. 합치기는 상황에 맞는 쪽 하나만 제안한다. 내 브랜치가 뒤처지면 "main 가져와 합치기", 끝났으면 "main에 합치기".
4. 지도는 작게, 일은 크게. 홈 위쪽에 두 줄짜리 작은 노선도만 두고, 화면 대부분은 고친 파일과 비교 보기에 쓴다. 전체 노선도는 "버전 기록"에서 본다.
5. 정말 되돌릴 수 없는 일만 묻는다. 덮어쓰며 올리기, 고친 파일 버리기처럼 작업 내역으로도 살릴 수 없는 일이다.

## 동작별 방식
| 얼마나 자주 | 동작 | 방식 | 묻는 것 |
| --- | --- | --- | --- |
| 하루 여러 번 | 고친 내용 보기 | 홈에 들어오면 첫 파일의 비교가 이미 열려 있음 | 없음 |
| 하루 여러 번 | 버전 저장 | 파일 목록 위에 제목과 설명. "화면.tsx 외 2개 고침" 같은 제안 이름이 들어 있음. Ctrl+Enter | 없음, 되돌리기 |
| 하루 여러 번 | 동기화 | 상단 바 버튼 하나. 가져온 다음 올린다. 다른 사람 버전과 겹치지 않으면 저절로 합쳐서 올림 | 겹칠 때만 충돌 해결 |
| 하루 여러 번 | 원격 확인 | 몇 분마다 저절로. 새로 고침 버튼 없음 | 없음 |
| 자주 | 브랜치 갈아타기 | 상단 바 브랜치 이름을 눌러 목록에서 고르면 바로. 고친 파일은 그 브랜치에 맡겨 두고 돌아오면 꺼냄 | 없음, 되돌리기 |
| 자주 | 새 브랜치 | 브랜치 목록 찾기 칸에 이름을 쓰고 Enter. 고친 파일은 새 브랜치로 따라감 | 없음 |
| 자주 | 방금 저장 취소 | 토스트의 되돌리기, Ctrl+Z | 없음 |
| 가끔 | main 가져와 합치기 | 작은 지도 옆에 "main에 새 버전 2개 · 가져와 합치기"가 뜰 때 누름 | 겹칠 때만 충돌 해결 |
| 가끔 | main에 합치기 | 브랜치 목록에서 지금 브랜치 옆 "main에 합치기". GitHub 프로젝트는 "검토 요청"이 기본 | 겹칠 때만 |
| 가끔 | 이 버전으로 되돌리기 | 버전 기록에서 역을 누르면 작은 메뉴. 기본은 기록을 남기는 되돌리기를 바로 실행 | 없음, 되돌리기 |
| 드물게 | 이 뒤 버전 지우고 돌아가기, 이 버전만 복사, 태그 | 같은 작은 메뉴의 "더 보기" | 올린 버전을 지울 때만 |
| 드물게 | 덮어쓰며 올리기 | 설정에서 켜야 보임 | 항상 묻기 |

## 버전 이름 쓰는 칸
| 앱 | 방식 |
| --- | --- |
| GitHub Desktop, Fork | 목록 아래 입력 칸 두 개와 버튼. 채팅창처럼 보임 |
| VS Code, Sublime Merge | 글상자 하나. 첫 줄이 제목, 나머지가 설명 |
| Linear, Notion, 메모 앱 | 큰 제목 아래 바로 본문. 테두리 없이 문서처럼 씀 |
| Figma, Google Docs | 먼저 저장하고 버전 기록에서 이름을 붙임 |

추천: 파일 목록 위에 문서 제목처럼 큰 글씨로 이름을 쓰고 바로 아래 설명을 쓴다. 제안 이름이 들어 있고 Ctrl+Enter로 저장한다. 비교안은 노선도의 지금 여기에 쓰기, 먼저 저장하고 이름은 나중에. 그림은 `img/flow4/r-note.png`, `r-cmp-map.png`, `r-cmp-later.png`.

화면 문구는 이름과 숫자만 남기고 설명 문장은 뺀다.

## 단축키
| 키 | 동작 |
| --- | --- |
| Ctrl+Enter | 버전 저장 |
| Ctrl+Z | 방금 한 일 되돌리기 |
| Ctrl+Shift+Z | 다시 하기 |
| Ctrl+B | 브랜치 목록 |
| Ctrl+Shift+S | 동기화 |
| Ctrl+H | 버전 기록 |
| ↑ ↓ | 파일 옮겨 가며 비교 보기 |

## 구현 메모
- 되돌리기는 hiGit의 journal과 백업 ref를 쓴다. 동작마다 "되돌리는 방법"을 Action에 함께 정의한다. Action 레지스트리에 `undo` 필드를 더하는 것이 가장 단순하다.
- 브랜치별로 맡겨 둔 고친 파일은 `refs/higit/parked/<브랜치>`에 stash로 둔다. 일반 임시 보관 목록과 섞이지 않게 한다.
- 겹침 미리 계산은 `git merge-tree --write-tree`로 작업 폴더를 건드리지 않고 한다. Git 2.38부터 쓸 수 있다.
- 동기화 중 저절로 합칠 때는 합친 버전 이름을 "민지의 버전 1개 가져와 합침"처럼 만든다.
